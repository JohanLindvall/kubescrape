# AGENTS.md

Guidance for coding agents (Claude Code reads this file natively; other tools read `AGENTS.md` by convention) working in this repository.

## Commands

```sh
make build              # build to bin/kubescrape (unstripped, for delve/gdb; release binaries strip -s -w)
make test               # go test ./...
go test ./internal/store/ -run TestWaitIsPerContainer -v   # single test
make vet fmt tidy
make lint               # golangci-lint v2 at the version the Makefile pins (installed into hack/bin; config .golangci.yml; `modernize` on production and test code — `go fix` applies it)
make race               # -race over the whole tree, default tags (CI)
make vulncheck          # govulncheck over the shipped TAGS (CI)
make image              # docker build; service is CGO_ENABLED=0 static, agent is CGO_ENABLED=1 (libsystemd) on distroless/base; journald-less TAGS use Dockerfile.static
make build TAGS=journald,azure   # optional-pipeline build tags; TAGS defaults to journald,azure,events
make verify-tags        # no cgo without journald, no franz-go without azure, no client-go without events; its LAST step, a tag-less `go build`, is the only step of `make check` that type-checks azure_disabled.go and events_disabled.go
make image-static       # Dockerfile.static: no journald ⇒ both binaries static on distroless/static; a TAGS_STATIC carrying journald is refused (it would build the cgo image under a -static tag). hack/tooling_test.go pins both image targets
make check              # fmt-check → vet → lint → helm-lint (bootstraps helm into hack/bin) → test → verify-tags. Tests the DEFAULT tag set and only COMPILES the other variants' stubs; CI adds the tag-less TEST run (`make build test TAGS=`), `make race`, `make vulncheck` and a -check-config run of each binary in both images
make e2e                # kind smoke test (hack/e2e.sh): image build+load, deploy/kubernetes.yaml + agent.yaml (events/servicegraph only by manifestcheck) + collector fixture, readiness, discovery, store lookup, telemetry at the collector, the protobuf scrape path. KEEP=0 tears down, SKIP_BUILD=1 re-runs against the loaded image
make chaos              # hack/chaos/*.sh against whatever `make e2e` left running: collector outage, agent SIGKILL, kubelet log rotation, API-server blackhole. Minutes each, deliberately NOT in `make check`
```

**Toolchain floor: Go 1.27.1 is a SECURITY and CI-PARITY floor, not a language one.** Nothing in the source needs it; the stdlib advisories that raised it, and what each is reached from, are listed in `docs/CONFIGURATION.md#toolchain-and-build-floor`. The `.1` is parity: `actions/setup-go` installs EXACTLY `go.mod`'s version, and it is the one the image builds with. The directive also selects the binaries' default GODEBUG, so moving it changes runtime behavior (`$(go env GOROOT)/doc/godebug.md`). The `go` directive enforces the Go half: `GOTOOLCHAIN=auto` downloads 1.27.1, `GOTOOLCHAIN=local` refuses, so the worst case is a loud build failure. It does NOT govern the non-Go half: both Dockerfiles use floating tags (`golang:1.27-bookworm`, `distroless/base-debian12`) and the agent image COPIES libsystemd plus six transitive `.so` files out of the build stage, so a cached base layer ships stale glibc into an image whose Go binary is current. Re-run `make vulncheck` rather than trusting the directive. `go.mod` is the only ENFORCED statement of the floor, but not the only one: move it together with the Dockerfiles' `golang:` tag, README's build line and that CONFIGURATION.md section, which all quote the version.

**Accepted residuals are documented, not buried.** A hole this repo will not close gets a comment at the code that leaves it AND, when an operator could act on it, an entry in `docs/CONFIGURATION.md`'s **Accepted security residuals** section, which is the roster. Read it there; this file deliberately does not copy it, because nothing ties a copy to the section.

**Docs are guarded like the manifests.** `docs/FLAGS.md` is GENERATED per binary (`flagsdoc_test.go` in each cmd package; `go test ./cmd/<binary> -run TestFlagsDocIsCurrent -update-flags-doc`). `TestFlagsAreMentionedInConfigurationDoc` fails when a registered flag is never mentioned in CONFIGURATION.md; `internal/docscheck` fails when a doc TABLE documents a flag neither binary registers (the registered set is the generated FLAGS.md). `internal/chartcheck` pins the RENDERED chart against golden files per value fixture — helm only at the version in `hack/helm-version` (majors differ in rendered whitespace); skips without it, FAILS under `CI`; regenerate with `go test ./internal/chartcheck -run TestChartGolden -update-chart-golden`. `docs/METRICS.md` is generated from the registrations in `internal/obs`'s non-test files (`go test ./internal/obs/ -run TestMetricsDocIsCurrent -update-metrics-doc`), and `TestDocumentedMetricsExist` fails if prose in README, this file or `docs/*.md` names a metric or LABEL that is not registered. `TestDefaultSetIsDocumented` (logscrub) requires this file, README and CONFIGURATION.md to enumerate the default scrub set in one place.

**Optional-compilation build tags** (`cmd/kubescrape-agent/buildtags.go` + the `*_enabled.go`/`*_disabled.go` pairs). `journald`, `azure` and `events` are POSITIVE tags and the DEFAULT IS CARRIED BY THE MAKEFILE (`TAGS ?= journald,azure,events`), so **a bare `go build`/`go test`/`go vet ./cmd/kubescrape-agent/` has NONE of them** — go through `make` or pass `-tags`. The mechanism is the file-level import: `startJournald`/`startAzure`/`startEvents` live in the tagged files, so a tag-less build never names `internal/agent/journald`, `internal/agent/azurediag` or `internal/agent/events`+`internal/leader`. Dropping `journald` removes the agent's ONE cgo dependency (fully static build); dropping `azure` removes 11 franz-go packages (~5 MB); dropping `events` removes `k8s.io/client-go` — more than half the stripped agent binary — which makes "the agent talks to no Kubernetes API" a LINK-TIME property. The shipped IMAGE is unchanged (all three tags on, and the metadata service links client-go anyway), so quote the agent figure as "an option, not a delivery". `cli.KubeConfig` lives in `internal/cli/kubecfg` because `internal/cli` is imported by every build. **The FLAGS never disappear** (`internal/manifestcheck` asserts every flag the manifests pass exists): `-journald`/`-azure-diagnostics`/`-events` on a build lacking the pipeline is a startup error naming the tag and the rebuild, raised first in `compileConfig` (`checkExcludedPipelines`), so `-check-config` catches it; each stub is one constructor returning an error, never a fake implementation. No `-config` section belongs to any of the three, so a shared ConfigMap decodes on every variant. The startup line and `-check-config` print `optionalPipelines=…`. The packages' own files are untagged, so their tests pass under any tag set.

`CGO_ENABLED=1 go test -race ./...` works (`make race`, as CI runs it); run it for concurrency-touching changes (store, metaclient cache, otlpingest). The concurrency tests in `internal/store` and `TestEnricherConcurrent` are the targeted exercises.

**Benchmarks use `b.Loop()`, and every allocation budget is ALSO a Test.** A benchmark cannot fail a build, so budgets are asserted by `TestXxxAllocationBudget`/`TestXxxIsAllocationFree` with `testing.AllocsPerRun` and an explicit ceiling (tailer line + flush, log-metrics, promparse per-sample and per-exemplar, promscrape's filter session and accumulators, logscrub no-match, spanmetrics Consume, servicegraph Record + Consume, tailsample Decide, tailbuffer late-drop and keep/drop decision). `b.Loop()` because the old loop form lets the compiler eliminate an unused body — the exact failure mode for a zero-allocation claim. Quote ALLOCATION counts, which are machine-independent — never ns/op (re-measurements on other or loaded machines differ severalfold) and never a warm-path B/op (a one-time construction divided by `N` shrinks with `-benchtime`). Work after the loop that `N` already counts (a trailing flush) is charged inside `b.StartTimer()`/`b.StopTimer()`: `b.Loop` stops the timer on exit, and uncharged work makes allocs/op scale with `-benchtime`. Budget tests SKIP under `-race` via `internal/testrace.Enabled` (ONE build-tagged const package imported only from _test files): the detector changes escape analysis, and widening a ceiling to survive it would let a real regression through.

**Error-building helpers WRAP their cause** (the model is `tailsample.errPolicy`): format in TWO steps, `fmt.Errorf("%s: %w", where, fmt.Errorf(format, args...))` — the inner call forwards `format, args...` VERBATIM, so go vet still checks every call site, and the outer `%w` keeps the cause reachable (`TestCompileErrorsWrapTheirCause`, `TestErrPolicyKeepsThePrintfWrapperShape`). A helper that takes a format string and does not forward it verbatim is the shape to watch for.

### End-to-end verification (kind)

**The collector fixture CAPTURES payloads.** `hack/otel-collector.yaml` runs the debug exporter AND a FILE exporter per signal plus a busybox `reader` sidecar (`kubectl exec -c reader -- cat /data/<signal>.json`; the collector image has no shell). At `verbosity: normal` the debug exporter prints a summary per push and one line per item (a log body + record attributes, a metric name + data-point attributes), which `hack/e2e.sh` greps — `basic` prints nothing and breaks the run with no hint why. It never prints the RESOURCE below `detailed`, so a resource attribute's VALUE can only be proved from the captured file — and raising it to `detailed` floods the collector's stdout, which the kubelet then rotates within seconds (capture with `kubectl logs -f`, not `--since`). Never truncate those files in place (the exporter holds an fd at its own offset; delete the collector POD for a clean slate), and a reader that stops early kills `kubectl` with SIGPIPE, which under `pipefail` reads as "no data" exactly when the data is there. An agent must exclude the collector's namespace (`-logs-exclude-namespaces`; the shipped manifests and chart do) or it feeds the collector its own output. After a collector rollout the agent's gRPC connection may keep delivering to the terminating pod for a while.

**Native histograms have a FIXTURE**: `hack/nhexporter` is a real client_golang target (native-histogram fields exist only in the protobuf exposition, negotiated from the Accept header the agent sends under `-scrape-native-histograms`), also exposing a classic histogram, an exemplar-bearing counter, a gauge and a summary. `FORCE_PROTO=1` makes it answer protobuf regardless — the misbehaving target the agent must refuse when the operator has not opted in (the format is the operator's choice, never the target's). The e2e asserts the refusal, that a well-behaved target negotiates down to text, and that schema→scale plus span/delta→dense buckets converts.

**Chaos scenarios** (`hack/chaos/*.sh`) run against the SHIPPED deployment `make e2e` leaves up; the DATA-PATH ones assert **NO GAP** in a densely numbered writer's sequence (duplicates are allowed and expected under at-least-once; a number produced and never delivered is loss), collector-outage and log-rotation also baseline-flat loss counters, and `apiserver-blackhole.sh` that `/readyz` latches, probe failures move and nothing restarts. Three rules learned by getting them wrong: a scenario must assert WHICH path its fault took (`agent-kill.sh` `kill -9`s the agent container's PID via `crictl` and asserts the pod name and restartCount); the collector-outage writer starts AFTER the collector is down (a scaled-to-zero collector's replacement has a fresh emptyDir); the rotation scenario ASSERTS THAT IT ROTATED before asserting the invariant (`hack/kind-config.yaml` sets `containerLogMaxSize: 1Mi`; a cluster created without it fails with a message saying to recreate it).

Changes to informer wiring, the store, or the HTTP API should be verified against a real cluster, not just unit tests:

```sh
make cluster-up         # 3-node kind cluster; downloads kind/kubectl into hack/bin unless matching (KIND_VERSION; KUBECTL_VERSION ±1 minor; an unrunnable one counts as a mismatch, hack/tooling_test.go); deploys hack/test-workloads.yaml
go run ./cmd/kubescrape # uses the kind kubeconfig context
make image && hack/bin/kind load docker-image ghcr.io/johanlindvall/kubescrape:latest --name kubescrape
kubectl apply -f deploy/kubernetes.yaml   # in-cluster deployment (namespace: monitoring)
make cluster-down
```

`hack/test-workloads.yaml` exercises every code path: a pod-annotated Deployment (ReplicaSet→Deployment chain), a non-annotated Deployment behind an annotated Service with a named `targetPort`, a CronJob (Job→CronJob chain), plus a StatefulSet and a DaemonSet (direct-owner chains).

## Public packages (`pkg/`)

`pkg/promparse` (the exposition parser; `internal/agent/promscrape` aliases its types), `pkg/kubemeta`, `pkg/metaclient`, `pkg/logattrs`, `pkg/otlpsplit` (size-bounded OTLP splitting) and `pkg/cgroupid` (cgroup path → pod/container identity) are importable by other modules and **must never import `internal/`** (Go allows it inside the module, but internal APIs would become public contract; `pkg/boundary_test.go` enforces it). `metaclient` has no metrics dependency (the agent passes `Config.Observe`); its constructor is `New(Config)` with everything set at construction and the transport overridable via `NewTransport()`; an undecodable response is a typed `*DecodeError`. `kubemeta.PeerIP` lives in `internal/peerip` (one implementation shared by `/v1/self` attribution and the agent's peer-IP fallback, so both key the pod-IP index identically); `logattrs.LoadConfig` lives in that package's _test file like every other standalone loader.

## Shared internal primitives

Decisions more than one package needs live in ONE package each. Reach for these before writing another copy:

- **`internal/bearer`** — a bearer token in a mounted file that rotates. `File` is the CLIENT half (per-interval re-read; a FAILED re-read keeps the last good value), `Rotating` the RECEIVER half (current contents plus predecessor for a grace window), `Authorized` the constant-time check (every candidate compared, no early exit, an empty candidate never authorizes). `Rotating.Tokens` re-reads with the mutex DROPPED but claims the refresh slot with a FLAG, never a deadline — a timestamp claim expires while a read is still blocked, and on a wedged mount every interval then pins another OS thread up to the runtime's fatal thread limit. `File.Token` shares the claim, and a claimer waits at most `refreshWait` — as does, with no token ever read, a caller finding the first read in flight (concurrent first uses must all get what a healthy mount returns in microseconds); the tier's gRPC auth tap, which must not wait, reads `Rotating.Cached`. Deliberately NOT unified: the initial read — `NewRotating` reads fatally (a receiver must never open a listener with an empty accept set), `NewFile` does not read (callers wanting a fatal first read call `File.Read`). A failed re-read counts `kubescrape_bearer_token_read_errors_total{role}` with a throttled Warn, because both halves survive it BY DESIGN and the symptom (a fleet-wide 401, minutes later) appears elsewhere. Out of scope: `azurediag/auth.go`'s token source, which refreshes on an issuer's expiry rather than a file mtime, and its connection string, read uncached per SASL session.
- **`internal/cli.SetMemoryLimit`** — the Go soft memory limit at 90% of THIS CONTAINER'S OWN cgroup limit, applied by both mains after the startup line. The GC sizes off the live heap and knows nothing of the cgroup, so a transient burst near `limits.memory` (the agent's scrape cycle) is OOMKilled rather than collected harder; the limit can only ever LOWER the heap goal, so it is pure tail insurance. The CODE reads the cgroup rather than the chart setting an env var because only one of three deployment paths can do helm arithmetic. It reads `/proc/self/cgroup`'s own path (both cgroupns layouts) with the mount root as the cgroup-v1 fallback, and deliberately NEVER an ancestor's limit (`kubepods.slice` carries the node's whole allocatable, so an uncapped container would inherit ~0.9x node RAM) and NEVER the host's MemTotal (an uncapped workload has nothing to insure; the metadata service ships uncapped on purpose). `GOMEMLIMIT` in the environment wins, `off` included (so the ENV VAR is read). A node hierarchy mounted OVER `/sys/fs/cgroup` reads as uncapped and Warns. GOGC is untouched; GOMAXPROCS needs nothing (Go derives it from a cgroup CPU limit since 1.25). `tailbuffer`'s `maxSpans` sizing calls the same reader (`cli.CgroupMemoryLimit`) and keeps its own MemTotal fallback.
- **`internal/config`** — `config.Duration(field, value, def, opts...)` is the one reader for an optional Go-duration config STRING (the agent's YAML decodes through encoding/json, which takes only raw nanoseconds for a `time.Duration`): empty = default, NEGATIVE = an error naming field and value, explicit `"0"` = off unless the call site says `config.Positive(why)`. `config.Glob` owns the parse-time `path.Match(pat, "")` probe (a malformed glob otherwise reads as silent no-match) for routing, tailer namespaces and the debug tap.
- **`internal/promdur`** — prometheus-operator's `y/w/d/h/m/s/ms` syntax, the ONE parser the monitor merge and the scraper share; `promdur.Interval` (parsed AND positive) is their one usability rule, and only each caller's REACTION is local (merge: the holder keeps; scraper: warn-once fallback).
- **`internal/cli.RegisterOTLPFlags`/`RegisterObsFlags`** — the flag blocks BOTH binaries register, registered once (`flags_test.go` pins the set; FLAGS.md lists it under both binaries); `otlpexport.ConfigFromFlags` is the block's one Config mapping and `OTLPFlags.SummaryAttrs` its one startup-line rendering (each main hand-picked its own and the service's dropped compression and skip-verify). `cli.CheckListeners` is the one listen-address check both dry runs run: an unparseable address refused by FLAG, and one socket = same normalised port with the same or a wildcard host (the service compared raw strings, so `:9090` beside `0.0.0.0:9090` passed and died at bind). Same move one level down: `otlpingest.DefaultContainerIDKeys`/`DefaultPodUIDKeys` and `tracesample.Config.SlowerThan`. **There is no `-log-format`**: both binaries emit logfmt only, which is what makes its correctness a property the package holds — `cli.NewLogfmtHandler` is `slog.TextHandler` plus a key sanitizer, and `internal/cli/logfmt_test.go` round-trips the repo's log shapes through the repo's OWN logfmt reader. VALUES round-trip; KEYS holding a space or `=` do not (TextHandler quotes them, the reader splits one attribute into two wrong ones), hence the sanitizer at every door keys arrive through (ReplaceAttr, `WithGroup`, a `slog.Group` at any depth, a group-valued `LogValuer` like klog's `ObjectRef`): an unsafe byte (TextHandler's rule, non-ASCII included) becomes `_`. Known non-round-trip: a control byte other than \n/\r/\t, pinned by test. Removing the flag was a FLAG-SURFACE change: the chart templates had to drop it in the same release or `manifestcheck` turns a diagnosable refusal into `flag provided but not defined`.
- **`internal/logdedupe`** — throttle a complaint about a persisting STATE so it does not flood proportionally to fleet size. `Throttle` is the KEYLESS half (one atomic + CAS on the MONOTONIC clock; the LOSER of the race stays silent), `Table` the bounded per-key half. **Saturation SUPPRESSES, it never clears** — the copy that aged entries out and cleared the map logged every key on every cycle forever at cap+1 keys; an existing key still re-warns under a full table. `Outage` tracks a RUN of failures (loud first, throttled after, one recovery line) — first-of-run, which a Throttle cannot express. Every failure-run narration uses it rather than a hand-rolled counter + timestamp + throttle (copies kept losing first-of-run), and its lines carry `failures`/`outage` (three spellings of one fact had drifted in); `otlpexport/report.go` alone keeps its own, since it also re-warns on an error-class CHANGE.
- **`internal/clip`** — cut a string to a byte bound on a rune boundary: `Runes`, `Marked` (marker only when it cut), `Ellipsis` (every log-attribute clip). Two of seven hand-rolled copies cut at the bare byte index and shipped half-encoded runes. The BOUND stays each caller's own (96 for a log attribute, 253 for a path segment, 512 for an echoed annotation). Not in it: `internal/metrics`' `truncLabelCut` (keeps invalid bytes on purpose — dropping the label would merge series) and `cumagg.Retain` (its COPY is the point).
- **`internal/agent/tracehash`** — the sampling arithmetic shared by the head sampler (`tracesample`) and the tail sampler's `probabilistic` policy (`tailsample`), plus the spans/second `Bucket`. Both hash the trace id UNSALTED against the same threshold so they NEST rather than compound (a 50% tail policy keeps exactly what `probability: 0.5` passed) and every trace decides identically across shards, retries and restarts; `Threshold` takes a FRACTION; the `MaxUint64` keep-all guard lives once. The Collector's decorrelating salt is deliberately not implemented. **Two hash functions on purpose** (both from `github.com/JohanLindvall/haste`): IDENTITY hashing, where a collision silently MERGES data, uses `haste/xxh3` at 128 bits — the log-metrics series key, the HTTP ETag, the disk buffer's stuck-payload key; DISPERSAL hashing uses `haste/rapidhash` (64-bit, no vector unit) — the sampling threshold, `logline`'s selector memo, the tailer's `obsKey` body hash. Do not "unify" them without that argument. The migration off zeebo/xxh3 was value-preserving (bit-identical); the move to rapidhash RE-ROLLED which traces are sampled (tracehash's doc carries the hazard). Out of scope: `servicegraph`'s `ring.TokenFor` (Tempo's FNV-1 on purpose) and the tailer's per-file `allowLine` bucket.
- **`internal/agent/logchain`** — the log-record chain and its key resolver; see the agent section.
- **`otlpingest.BodyReader`** (`httpbody.go`) + `WriteBodyError`/`WriteProto` and `GRPCForwardStatus`/`HTTPForwardStatus` (`forwardstatus.go`) — the OTLP/HTTP request seam every receiver uses. The cap is a parameter (16 MiB for application pushes, `sgMaxRecvBytes()` on the tier's internal hop — at least `otlpingest.MaxPushBytes`, since an over-cap span ships alone); the byte budget is optional.
- **`internal/regexcost`** — `Insts` estimates a pattern's compiled program from its PARSE tree (regexp/syntax's own `calcSize`, saturating at limit+1), so a data-derived pattern is refused before the compile that would be the cost; the attrs templates and transform's `re` builtin share it, while their refusal policies and caches stay their own.
- **`internal/peerip`** — what both binaries read off a connection to decide whose it is: `From`/`Canonical` (the one form the pod-IP index keys on) and `ForwardingHeader` (the one forwarding-header list, by PRESENCE, that `/v1/self` and the agent's debug guard refuse on — the two copies had drifted over `Via`).
- **`servicemonitors.Endpoint.secretRefs`** — the one list of secret-bearing endpoint fields, used by both monitor parsers (namespacing) and by `AuthSecretRefs` (allowlisting). A security boundary: a field updated in two of three places used to fail only at runtime, as `up=0`.

## Architecture

Two binaries: `cmd/kubescrape` (metadata service) and `cmd/kubescrape-agent` (per-node DaemonSet: log tailer + Prometheus scraper exporting OTLP). Both live in one image; the DaemonSet overrides `command: ["/kubescrape-agent"]`.

### Metadata service

`cmd/kubescrape` serves pod/container metadata over HTTP, driven by one initial LIST + WATCH per resource (client-go informers); there is **no per-request API-server traffic**.

- **Pod informer** (full objects) → `internal/store.Store`: pods by UID with FOUR derived indexes — normalized container-ID → entry, nodeName → pods, `byPodName` ("ns/name", with the same-name-replacement guard a missed delete would otherwise leak through), and `byPodIP` → the live claimant, backed by `ipClaimants` (EVERY record reporting an address, so a release promotes a survivor without an O(pods) scan under the write lock). The IP lifecycle rules (claim, release, promote, `ipSeq` ordering) are pinned by `podip_delete_test.go`/`ipclaimants_test.go`; a FIRST SIGHTING of a draining pod takes no sequence (the initial LIST is in name order). The transform `trimPod` strips `managedFields` and, for PODS ONLY, the spec bulk that never reaches `kubemeta.Pod`; Service specs are kept intact because `services.Index` reads them (`TestTrimPodPreservesEverythingFromPodReads` keeps the two in step).
- **Service informer** (full objects) → `internal/services.Index`: selector matching of Services to pods, for service-annotation discovery.
- **Metadata-only informers** (`PartialObjectMetadata`) for ReplicaSets, Deployments, StatefulSets, DaemonSets, Jobs, CronJobs, Namespaces, Nodes → `internal/owners.Resolver`. StatefulSets and DaemonSets own pods DIRECTLY (cached for labels/annotations, not for a chain). Owner chains and namespace metadata resolve **lazily at request time**, never stored on the pod. A new owner kind means one `owners.ownerKinds` row, `attrs`' `kindTable` and BOTH ClusterRoles (`deploy/kubernetes.yaml`, the chart's). **Readiness gates on the HANDLER REGISTRATIONS' `HasSynced`, never the informer's** (`registerCoreInformers` returns `podReg.HasSynced`/`svcReg.HasSynced`; pinned by `TestCoreGatesWaitForTheHandlersNotTheInformer`): the store is filled from inside the handlers, and gating on the informer served 200 while the store was still filling. Owner informers legitimately use the informer's (their lister reads its indexer). ServiceMonitor AND PodMonitor informers are both gated (`startServiceMonitors` returns a gate per watched kind; `TestMonitorGatesCoverEveryWatchedKind`) — an unawaited PodMonitor informer once 403-looped forever behind a green `/readyz`. A discovery error is FATAL, never read as "the CRD is absent" (`monitoringResources` returns the served RESOURCE NAMES plus an error; only NotFound/NoMatch becomes an empty map — a cluster can serve other `monitoring.coreos.com/v1` kinds without `servicemonitors`). `-monitor-namespaces` restricts whose monitors are honoured (empty = all), applied at INDEXING time so a refused monitor never widens `AuthSecretRefs`; without it anyone who can create a ServiceMonitor in their own namespace can point every agent at an arbitrary path cluster-wide. **Readiness LATCHES, and the compensating signal is a REACHABILITY PROBE, not the watch-error counter** (`cmd/kubescrape/apiserver.go`, `-apiserver-probe-interval`, 30s, 0 disables): flipping `/readyz` during an outage would drop the pod from its Service and cut every agent off a cache still serving useful data, and the watch-error counter does not fire for the likeliest outage (client-go retries a refused connection inside the reflector without ever returning; a broken stream logs at INFO and returns nil). The watchdog issues a `limit=1` metadata list of Namespaces (already-watched resource, no new RBAC; no `resourceVersion`, so it fails when etcd does), publishing `kubescrape_apiserver_reachable` + `kubescrape_apiserver_probe_failures_total` with a transition WARN, throttled re-warn and recovery INFO. Alert on it SUSTAINED: it proves a NEW connection reaches the API server, not that the caches advance. The store gauges are no staleness signal either — the sweeper keeps expiring tombstones, so `kubescrape_store_pods` DECAYS during an outage rather than freezing. **`kubescrape_owner_resolve_failures_total{kind,reason}` is the resolver's ONE signal**: a failed read returns nil and appends the BARE owner reference, which renders as a well-formed response while `attrs.ServiceName` silently falls back to the pod name. Read the REASONS, not the total: `not_found` is the only normal one (a tombstoned pod outliving its owner, a cache still filling — a low steady rate is expected, a SUSTAINED high one means the owner informer is not seeing objects); `lister_error`/`no_informer`/`wrong_type` are never normal and carry a throttled Warn; `bad_api_version`/`uid_mismatch` are per-object oddities (an owner deleted and recreated under its old name is refused rather than lending the recreated object's labels). `kind` comes from the GVR (or `knownKind`, bounded to `ownerKinds` + `unknown`), never the raw reference, and the reason strings are spelled once in `owners.go` because `obs`'s help text enumerates them.
- **ServiceMonitor/PodMonitor CRDs** (opt-in `-servicemonitors`, dynamic informers over unstructured) → `internal/servicemonitors.Index`. Targets resolve monitor → Services (`services.All(m.ServiceNamespaces())`) → pods, so scraping stays node-local; `scrape.MonitorTargets` handles endpoint `port` (service-port name) / `targetPort` (pod port) / `path` / `scheme`, stamping `Source: "servicemonitor"` + `Monitor: "ns/name"`; an endpoint naming NEITHER port nor targetPort resolves to nothing (`""==""` must not match an unnamed port). PodMonitors select PODS directly (`scrape.PodMonitorTargets`, `Source: "podmonitor"`). The authoritative ignored list is `endpointSpec.ignoredFields()` + `specLimits.ignored()` — prose drifted from it three times.

It moves none of the DERIVATION's decision counters; its shared owner/namespace enrichment still counts.

Both binaries run `obs.Registry.Run` on `-self-metrics-interval` (1m, 0 disables) with their own resource identity (agent: `service.name=kubescrape-agent`+node; service: `kubescrape`+hostname). **Three listeners** (both binaries): `-listen` (health + `/debug`), `-metrics-listen` (`:9090`, `GET /metrics` via `obs.ServeMetrics`: Go runtime/process metrics from client_golang ALWAYS, plus the `kubescrape_*` Registry metrics exactly when `-self-metrics-interval=0` — ONE knob selects the delivery modality, so nothing double-delivers), and `-pprof-listen` (empty by default; profiles carry goroutine stacks and heap contents, so that port is the one to firewall). The scrape reads `metrics.Registry.Dump` + the `registryCollector` bridge in `obs/runtime.go`; Dump is NON-MUTATING by contract (`TestDumpNonMutating`) so it can never steal samples from the push (`series.snapshot` via `Registry.Export`, which consumes state, stays the push path's). The chart stamps `prometheus.io/*` on both pods, so the agents scrape their own runtime metrics. `GET /readyz` on the agent is a REAL readiness check (`readiness` in `cmd/kubescrape-agent/readiness.go`): gates registered at startup, 200 only when none are pending (listed in the body); the `metadata-service` gate clears on the first node-metadata fetch. `-check-config` compiles every section via `compileConfig` (`validateConfig` is its verdict-only face; a real start consumes the result) and exits without acquiring any resource — a new config surface must be added to `compileConfig`. New failure paths count into an existing `obs` metric or add one; tests read values via `Value()`.
- **HTTP metadata caching**: the service stamps metadata 200s (container/pod/pod-uid/node AND node-targets — deliberately NOT pod-ips) with `Cache-Control: max-age` + `ETag` (`server.writeCached`, `-metadata-cache-ttl` 10s, 0 disables); the targets response is SORTED (URL, then monitor/source) before hashing, since `PodsOnNode` iterates a map; `metaclient` keys its cache on the query-less URL and revalidates stale entries with `If-None-Match`. **The node-targets memo is validated by a CHANGE TOKEN, not a clock** (`server.targetsValidity`, `nodeTargetsETag.valid`): every source `nodeTargets` reads — the node's pod set (`Store.NodeGeneration`), the owner/namespace caches (`owners.Changes`, fed by a handler `cmd/kubescrape` registers per owner GVR but Nodes), `services.Index`, `servicemonitors.Index` — publishes a generation that advances only on a REAL change, and a revalidation whose four tokens agree is answered 304 with a FULL max-age. Before this the memo lived for `cacheTTL` and the 200 advertised the same `cacheTTL`, so a conforming agent re-asked exactly when the memo lapsed and re-paid the whole derivation on every poll. Three load-bearing rules: a writer bumps AFTER its mutation is visible; a reader samples the token BEFORE reading; the token is AUTHORITATIVE when available (a mismatch rebuilds even a young memo). It advances only on real change: a resync re-delivering a byte-identical object returns at `resyncNoOp`, and the owner handler compares the SERVED PROJECTION — labels, annotations, owner references (`owners.SameServedRefs`, only what is served) and the UID — rather than `resourceVersion`, which status-only writes rewrite constantly (a kubelet rewrites its Node every 5 minutes; `TestStatusOnlyUpdatesDoNotAdvanceTheOwnerToken`). An UNWIRED source drops to the wall-clock fallback (`targetsValidity.wired`; `TestNodeTargetsMemo304GrantsOnlyTheRemainingTTLWithoutAChangeToken`), since a source that publishes nothing is indistinguishable from one that never changes; `TestNodeTargetsMemoRebuildsWhenAnySourceChanges` is the safety pin. The client cache is mutex-guarded (shared across ingest handlers) and stores ONLY the decoded value (hits and 304s shallow-copy it out under the treat-as-immutable contract); an undecodable 200 is an error and never cached; `Client.now` is injectable.

### Invariants the API guarantees (user requirements — do not regress)

- **One pod's targets are BOUNDED** (`scrape.MaxPortsPerPod`, enforced in `server.targetDedup.add`, where targets are ACCUMULATED — a cap at any single door was walked past by a ServiceMonitor's endpoint list). Every `ScrapeTarget` embeds the whole pod, so N targets is an O(N²) response that OOMs the singleton. Applied on the NEW-URL arm only (endpoints merging into a URL the pod already holds are free). A refusal moves `kubescrape_scrape_targets_capped_total`, `/v1/explain` names it (`cappedTargets` plus a note through the one wording `scrape.CeilingNote`) and a throttled WARN names the pod and workload. `add` RETURNS its verdict because only the accumulator can name a refusal (two doors individually under the ceiling overflow together). The scrape-side mirrors carry each door's own cap (`portFilter.kept`, `servicePortFilter.kept`).
- **One target's RELABEL CHAIN is bounded, which the target COUNT cannot do** (`servicemonitors.maxRelabelRules`/`maxRelabelChainBytes` at parse, `scrape.MaxRelabelChainRules`/`MaxRelabelChainBytes` at merge): `metricRelabelings` is tenant-authored, copied into every target and walked per SAMPLE by every agent (one 20,000-rule monitor made a 10-pod node's document 19 MiB). Two bounds because merge CONCATENATES. Both AGGREGATE bounds keep the PREFIX and refuse the tail — fail-OPEN for the tail, stated at the constants, because refusing the CR would take every target it contributes. The PER-RULE bound (`maxRelabelRuleBytes`, equal to the chain budget) refuses the ENDPOINT via `Endpoint.Refused`, because dropping one oversized `keep` allowlist silently inverts it into export-everything. Reported at both doors (`Endpoint.Ignored` → `kubescrape_monitor_fields_ignored_total` at parse; `kubescrape_monitor_relabel_chain_capped_total{kind}` + throttled warn + explain note at merge) because it is INVISIBLE in the data. `relabelChain` returns the applied rules and the report from ONE walk over the WHOLE list, measuring the per-rule ceiling BEFORE the aggregate ones (a `break` at the aggregate ceiling left an oversized rule past it unmeasured, turning the documented fail-closed into a silent fail-open). It also refuses the ENDPOINT on an admitted regex the agent cannot compile (`kubemeta.CompileRelabelRegex`) or a keep/drop reading a label an earlier unapplied mutating rule writes (`relabelWrites`; an action-less rule is the default `replace`). Source BYTES do not bound COST (counted repetition expands at compile, case-folded ranges and `\p` tables while parsing), so every admitted rule is also charged `kubemeta.RelabelRegexCost` against `maxRelabelChainCost` exactly like its bytes (per rule = per chain); the door PARSES and never compiles, and `relabelWrites`' held predicates share one cost budget (over it = fail closed).
- **The ENDPOINT LIST is bounded at the parse door** (`servicemonitors.maxEndpointsPerMonitor` = 128, in `parseMonitorSpec` for both kinds): 100,000 endpoints (inside etcd's object limit, writable by one tenant) parsed into ~38 MB retained per CR, a million-entry monitor→services memo and ~1.7 s per node-targets derivation, with nothing in the served document to show for it. Prefix kept, tail refused under the CRD's own field name (`endpoints(capped)` / `podMetricsEndpoints(capped)`) into the monitor-level `Ignored`. The cut precedes the decode. SELECTORS are bounded too, refusing the MONITOR (a dropped term WIDENS it). NOT bounded: the informer's cached CR.
- **One target's CONTRIBUTOR LIST is bounded too** (`scrape.MaxContributorsPerTarget` = 32, the wire-visible `Monitors`): N monitors carrying no relabelings, all resolving to one URL, reach no other ceiling, and the list was O(n²) per pod. What is refused is ATTRIBUTION, never configuration (the merge already happened; only a name stops being listed). Counts `kubescrape_monitor_contributors_capped_total{kind}` plus a throttled warn keyed by the **URL** (keying by monitor gave one line per refused CR); `/v1/explain` has the per-monitor answer.
- **Under all of those, one pod's targets are bounded in BYTES** (`scrape.MaxTargetBytesPerPod` = 256 KiB, charged in `targetDedup.add`, measured by `scrape.PodDocBytes`/`TargetDocBytes`): the count cap models a target as ~2 KiB, and a pod's own labels (bounded only by the ~1.5 MiB object size; annotations are now bounded at the source, below) break the model from inside it — ~200 KiB of labels with 16 port entries gave a 3.3 MB body, and `writeCached` must BUILD the body to hash its ETag. The charge is the WHOLE target document, so every present and future per-target string is inside it by construction. **The pod's FIRST target is unconditional**: the ceiling bounds the MULTIPLIER, never the workload, and the residual is one pod document per pod, which `/v1/pods/...` already serves. Measured ONCE PER POD, lazily, by a walk over map ENTRIES (0 allocs — a `json.Marshal` would allocate the very document being defended against). Refusals move the same `kubescrape_scrape_targets_capped_total`; `add` returns WHICH ceiling refused (`targetVerdict`) so explain tells them apart (`cappedTargetsBySize`, `podDocumentBytes`, `scrape.SizeCeilingNote`, whose remedy — shrink the annotations or split the ports — is the opposite of the count ceiling's). The merge arm IS charged (`scrape.MergeReport.Bytes` → `targetDedup.charge`) but refuses nothing (a refused merge would change what is EXPORTED). The SWAP arms are charged too, cutting a Service VIEW that does not fit to its identity (`scrape.ServiceIdentityView`), warned per Service and reported as `serviceViewsTrimmed` on `/v1/explain`; the pod's first target is exempt.
- **Under THAT, the pod DOCUMENT itself is bounded** (`kubemeta.MaxAnnotationValueBytes` = 8 KiB, `kubemeta.MaxAnnotationBytes` = 16 KiB, `owners.MaxOwners` = 8) — fixing the SOURCE instead of adding another per-target bound. The document carries the pod's annotations, its NAMESPACE's (copied per pod) and one set per resolved ownerReference, and Kubernetes bounds neither the owner count nor what an owner annotates (100 fat ReplicaSets named by every pod put ~25 MB in EACH pod document). Bounded at the ONE door every object goes through (`kubemeta.CopyMeta` → `FilterAnnotations`): a value over 8 KiB is omitted WHOLE, never truncated (a half-rendered template looks like it worked); the set is bounded at 16 KiB with `prometheus.io/*` and `kubescrape.io/*` admitted FIRST in deterministic order (an arbitrary subset would mint a fresh ETag per poll; a budget starving `prometheus.io/scrape` would silently stop scraping). Preserved keys are admitted first, not EXEMPT. The owner count is bounded at 8 against a legitimate maximum of two. **Every refusal is visible**: `kubescrape.io/annotations-omitted` on the object's own annotations (a cluster-supplied copy is stripped at both doors via `refusedAnnotations`), `kubemeta.Pod.OwnersOmitted` on the wire, `obs.MetadataAnnotationsOmitted{kind}` and `kubescrape_owner_resolve_failures_total{reason="owners_capped"}` (logged once per resolution through a KEYLESS throttle — a keyed one would mint an entry per pod), and `/v1/explain`'s `annotationsOmitted`/`ownersOmitted`. The fast path is unchanged at 2 allocs (ceilings checked from LENGTHS inside the one copy loop). Counting happens in `store.UpsertPod`, `owners` and `services.Index.Upsert` because `pkg/kubemeta` cannot import `internal/obs`. **STILL NOT BOUNDED: A POD'S AND A NAMESPACE'S LABELS.** A pod's are selection input (Service and PodMonitor selectors), so no filter can know which one is load-bearing and refusing one would change WHAT IS SCRAPED; a namespace's are admin-owned attributes; a value is ≤63 bytes but the count is bounded only by the object ceiling, so ~1 MiB of them is possible — which is what `MaxTargetBytesPerPod` binds on, why `internal/server`'s fat-pod fixture builds labels, and an accepted residual. An OWNER's labels ARE bounded (`kubemeta.CopyOwnerMeta`, 16 KiB; refused keys named in `kubescrape.io/labels-omitted`, counted `kubescrape_metadata_labels_omitted_total{kind}`): nothing selects on them.
- **Container lookups block per container ID.** An unknown ID registers a waiter keyed by that exact ID; pod-upsert wakes only those; concurrent requests for one ID are all released. Bounded by `-wait-timeout` (a client's `?wait=` can shorten, never lengthen); it covers the ~1s before the kubelet posts the ID. **A parked lookup is ANSWERED on shutdown, never dropped**: `Server.Drain` (before `srv.Shutdown`) releases the store's per-ID waiters and `waitReady`'s pre-sync park (whose `ready` channel a failed `WaitForCacheSync` never closes), each returning 503 + `Retry-After: 1`. Only the store half moves `kubescrape_container_lookups_drained_total` (a sibling of the shed counter, not the same series — a rolling update must not page like abuse). `http.Server.Shutdown` does not close active connections at its deadline; the expired budget warns with the in-flight count instead of being swallowed.
- **Deleted pods stay resolvable via the container endpoint for `-cache-ttl`** (tombstone: `expireAt` + `deletedAt`, swept periodically). Restart-replaced container IDs get the same TTL; `lastState.terminated` IDs are indexed while the pod lives. That HISTORICAL record (`kubeconvert.previousIncarnation`) clears `Image`/`ImageID` (the terminated state carries no image, and `spec.containers[].image` is mutable in place) and sets `RestartCount` to N-1, the count the terminated run actually had.
- **Scrape targets never include deleted, finished or TERMINATING pods**: `DeletePod` removes the pod from the node index before tombstoning; `Succeeded`/`Failed` pods and pods with a `deletionTimestamp` (`kubemeta.Pod.DeletionTimestamp`, the single source of `record.terminating`) are excluded by `scrape.Scrapeable` — a draining pod stays `Running` for its whole grace period, so scraping it is pure `up=0` churn. All remain resolvable by container ID / UID / name. `kubemeta.Pod.Ready` is metadata only — a not-ready pod IS scraped.
- **`prometheus.io/port` is a comma-separated list** (numbers and/or names) on pods and Services; service ports translate via `targetPort`. **A port NAME resolves to exactly ONE port, identically on every path** (`scrape.containerPortByName`): a REGULAR container's declaration beats an init/sidecar or ephemeral one, then the first wins — `FromPod` appends init containers FIRST, so document order handed a native sidecar (`restartPolicy: Always`) the app container's port name, the opposite of `podutil.FindPort` and the EndpointSlice controller. A name no regular container declares still resolves from the fallback pass (`/v1/explain` says which case it took). Duplicates reachable via pod and service annotations dedupe by URL (pod source wins; a monitor target upgrades an annotation one wholesale). Two monitors on one URL → one merged target (above).

### Concurrency model

One `sync.RWMutex` in `store.Store` (plus one in `services.Index`) guards everything. The goroutines that TOUCH the store: the HTTP handlers, the informer callbacks, the sweeper (`Store.Run`), the cache-sync reporter (`st.Stats()` once in `waitForCaches`), the self-metadata poller (`selfResolver` → `st.GetPodByName`) and the self-metrics reader (the store's GaugeFuncs, under its RLock). `cmd/kubescrape` runs more that never touch it (the watchdog, `bearer.Rotating.Run`, the listener). Every mutation of a stored record happens under the WRITE lock — upserts replace whole records, and the one in-place write is `DeletedAt` on the tombstone path — so shallow copies under RLock are safe. The invariant is the lock, not immutability: a lock-free read path would race `deletePodLocked`. `FromPod` deep-copies everything it takes from informer objects; never retain or mutate an informer-owned object. Store tests use an injectable clock (`s.now`); follow that pattern instead of sleeping (tailer tests start via `startTailer`, which waits on Run's `initialScanned` hook and shortens the 2s discovery cadence). `t.Parallel()` only where a package is genuinely free of shared mutable state (`tailsample`, `route`, `logline`, `logattrs`, `peerip`): `cmd/kubescrape-agent` mutates process-global flags, `internal/metrics` pins a shared test clock, and an `AllocsPerRun` assertion must never run concurrently with anything.

### Panics: there is no `recover()`, and none is wanted

Neither binary contains a single `recover()` and **new code must not add one**. A panic is a bug, and letting the process die is the loudest honest report: the workload restarts, CrashLoopBackOff is visible, and the crash costs no RAW telemetry beyond `tailbuffer`'s undecided spans (which say so), because every producer's accounting is built for a hard kill (log offsets, the journal cursor, the events position and the Kafka offsets all re-read; the disk buffer commits only after an ack). What a hard kill DOES lose is in-memory state DERIVED from input already committed or acked: log-derived, span-metric, service-graph and self-metric observations since their last export (the cumulative series restart as a reset), the pairing store's unpaired half-edges and `cgroupstats`' open window — accepted as the price of an honest crash. A recovered panic leaves ONE pipeline silently dead inside a process still answering `/readyz` 200 — the failure mode the readiness gates and per-pipeline counters exist to make impossible. The asymmetry a review WILL rediscover: **`net/http` recovers a handler panic (drops that connection) and grpc-go does not (whole process)**, so the same malformed push crashes the process on the unauthenticated gRPC arms and merely drops a connection on HTTP. Accepted, not fixed: a recovery interceptor would convert a crash into the silently-dead-pipeline case, on the path where a panic most likely means a real parsing bug. A panic reachable from a receive path is a **bug to fix at the parse/convert seam**, next to the checks `pkg/promparse`, `protoparse` and `pkg/otlpsplit` already carry — never something to catch.

### Logging: logfmt, one vocabulary, and what is deliberately not logged

Both binaries log through `cli.NewLogfmtHandler`, installed BEFORE flags are parsed so every refusal `run()` RETURNS is logfmt, including those that precede the leveled logger (an unknown `-log-level`, a missing `-node-name`) — a flag-PARSE error is not: `flag.Parse` prints its own plain-text message and usage and exits 2 (docs/FIRST-RUN.md quotes it). Both route client-go's klog into it (`klog.SetSlogLogger`); logr's `err` becomes `error`, and the stdlib `log` bridge is at WARN (net/http's panic stacks). The key vocabulary is `internal/cli`'s package doc — extend it, never invent beside it: `error` (never `err`), `path` (never `file`; a credential file is `tokenFile`), `dir`, `url`, `endpoint`, `addr`, `peer` (`peerip.ForLog`), `namespace`, `pod`, `node`, `container`, `uid`, `id`, `target`, `monitor`, `kind`, `signal`, `pipeline`, `route`, `unit`, `key`; `interval`, `timeout`, `budget`, `backoff`, `wait` (a budget), `elapsed` (a finished step; never `took`/`waited`), `grace`, `attempts`, `failures`/`outage`, `bytes`, plural count nouns; `reason`/`outcome` matching the metric label, `flag` (dashed value), `note`, `version`, `built`, `hash`. Lowercase single words, lowerCamelCase for multiword, never snake_case. `TestNoLogCallUsesANeverSpelling` refuses the NEVER spellings (`err`, `cause`, `file`, `ns`, `podNamespace`, `podUID`, `remoteAddr`, `took`, `waited`) at every log call. **slog evaluates its arguments eagerly**, so a Debug call whose arguments cost more than a field read is guarded by `log.Enabled(ctx, slog.LevelDebug)`. **Hot paths take no per-item logging** — a counter plus at most a throttled aggregate line from the sweep or flush; the allocation budgets are the enforcement, and widening one to fit a log line is the change to refuse. **A persisting condition is throttled through `internal/logdedupe`** (`Throttle`/`Table`, a failure RUN through `Outage`, `Throttle.AllowAt` for a holder on an injectable clock), not a hand-rolled timestamp; one that stays hand-rolled argues why at the code (`otlpexport/report.go` re-warns on an error-class CHANGE, which no throttle expresses). **Never log a secret** — the ref, the length or the key name, never the value; `tokenFile` is a PATH.

Levels: **Error** = a pipeline is dead and a human must act; **Warn** = something unexpected the code handled (a fallback, a refusal, a truncation, a drop); **Info** = lifecycle an operator wants without asking, quiet in steady state; **Debug** = the per-object decisions that answer "why did it do that?".

**Every start is self-describing**: five `effective ...` Info lines (`configuration` / `destinations` / `listeners` / `identity` / `limits`), credentials only as the PATHS they are read from; the agent emits the SAME lines from `-check-config` via the same `printConfigSummary`, so a dry run and a rollout cannot describe different agents. **A readiness gate that will not clear says so**: both binaries warn after a 30s grace naming the pending gates under `gates` (one loop, `cli.WatchGates`, behind the agent's `readiness.watch` and the service's `waitForCaches` over NAMED `syncGate`s, since client-go's `WaitForCacheSync` can only say "not synced") and publish `kubescrape_readiness_gate{gate=...}`, because a replica stuck unready has no Service endpoints and nobody who can curl it. The operator-facing half is `docs/FIRST-RUN.md`.

### Node agent (`internal/agent/...`)

The agent talks only to the metadata service (`metaclient`) and an OTLP gRPC collector (`otlpexport`, built on `go.opentelemetry.io/collector/pdata`) — no Kubernetes API, no RBAC except `nodes/metrics` and `nodes/stats` for the kubelet scrapes. **The ONE exception is `-events`**, which runs as the cluster-singleton Deployment and is the only reason this binary can link `k8s.io/client-go`; under `TAGS=journald,azure` it cannot, and `make verify-tags` fails the build if an import puts it back.

- **Resource attributes** (`agent/attrs`): `attrs.Builder` (nil = defaults) runs defaults → static → config templates (funcs env/coalesce/default/regexMatch/regexReplace; context Node/Pod/Container/Service) → `attrs.Filter`, driven ENTIRELY by the config's `resourceAttributes` section (`enable:`/`disable:` are LISTS, because a comma-separated flag could not express a pattern containing a comma; the filter is global, so a `pipelines:` section setting them is REJECTED). `attrs.Builders` holds one per pipeline (`attrs.pipelineNames` is authoritative: logs/targets/cadvisor/node/summary/journal/ingest/self; `validatePipelines` prints it on a typo). `summary` governs only the `/stats/summary` NODE resource; that scrape's pod/container/volume resources are the CADVISOR pipeline's, because the two series join only while byte-identical. The defaults set `k8s.pod.ip`, derive `service.name` via `attrs.ServiceName` (workload owner → pod name), then `attrs.Identity(res)` derives `service.namespace` (= k8s namespace) and `service.instance.id` (fallback order container.id, pod-uid[/container], namespace/pod[/container], node) for Mimir job/instance — neither overwritten if a template set it; it works for pre-populated (splitter, ingest, log-metric) resources too. **Instance-collision avoidance** (`attrs.PrefixInstance`): an exporter that DESCRIBES other objects (cadvisor, a KSM splitter) shares the described pod's `service.name`/namespace and would collide with its self-scraped metrics on (job, instance) — flapping target_info. `instancePrefix` prepends `prefix-`; `defaultInstancePrefix` holds TWO entries (cadvisor → `cadvisor`, summary → `summary` — the kubelet's summary node resource otherwise collides with the `-node-metrics` scrape's on one (job, instance) with two `up` values). Precedence: explicit pipeline section > built-in default > top-level base (a global `instancePrefix: ""` leaves `summary-<node>` standing). Split rules default it to the describing target's `service.name` (`SplitRule.InstancePrefix`, `""` disables), take `dropLabels` (anchored regex) and `attributes` (set-if-absent fallbacks in `fillSplitResource`), and may map several groupBy labels to one attribute (applied in sorted label order, non-empty overwrites — the ROUTE KEY, the enrichment identity and the rendered attributes read ONE coalesced vector, or two spellings of one object minted duplicate resources). On split resources the rule's `datapointAttributes` (default `["k8s.node.name"]`) move off the resource onto the data points (`splitBatcher.route`/`putSplitLabels`); `[]` keeps everything on the resource. Every point that builds a final resource calls `Attrs.Build`; new resource-producing code paths must too. `.Node` comes from `GET /v1/nodes/{name}/metadata` via `startNodeInfo`.

- **Exporter** (`agent/otlpexport`): gRPC or OTLP/HTTP; every wire send returns through `Client.noteSend`, counting `kubescrape_export_requests_total{signal,outcome}` (ok/transient/permanent — "collector down" and "telemetry lost" are different alerts) and reporting through TWO lines (`report.go`): a TRANSIENT-only destination narrative (transition Warn, 5m re-warn, recovery Info) and a stateless throttled per-signal permanent-rejection line (`noteRejected`: `class=permanent`, `rejected=`, `over=`) — a permanent verdict is on the payload, and routing it into the state machine flapped warn/recovery per export; both carry the `Diagnose()` note; split parts count `kubescrape_export_split_parts_total{signal}`. Bearer token via `internal/bearer` (a failed re-read keeps the last good token), TLS CA/skip-verify, bounded retries for metrics only (log retries belong to the tailer; `Retry` waits through `backoff.B`, so every wait — an over-cap initial included, which `backoff.New` clamps — stops at `backoff.Cap` like every other doubling delay — `-otlp-retry-attempts` has no upper bound). **Size-bounded sending** (`pkg/otlpsplit`, `-otlp-max-send-bytes` ≈3.75 MiB under the 4 MiB gRPC limit): every send measures the exact proto size and splits an over-cap payload preserving resource/scope grouping (over-cap resource → by record/metric/span; over-cap metric family → by DATA POINT, all five types; a single over-cap leaf goes alone). A part failure returns immediately and the caller retries the whole payload (at-least-once). A non-empty input never yields zero parts. **The AMPLIFICATION bound** (`otlpsplit.splitPaysOff`, `minChunkRoomDiv` = 4): each chunk re-copies its framing, so a payload whose framing sits just under the cap would split into one part per record; past the threshold the split is ABANDONED and the remainder ships as one over-cap part (same outcome, one round trip). d=4 so a Kubernetes-derived resource (annotations ≤256 KiB) can never trigger it. Reported via `otlpsplit.Report` → `kubescrape_export_oversize_parts_total{signal,reason}` (`item`/`framing`), throttled warns, counting only parts whose encoded size is over the cap. Payloads gzip by default (`-otlp-compression=gzip|none`, klauspost): `gzip.go` registers a klauspost gRPC "gzip" codec (never also import grpc's — last init wins) and pools READERS as well as writers (grpc-go gzips the two-byte response too). Release contract: the wrapper returns the reader on the FIRST of a terminal Read or Close, exactly once, under a mutex; Close is NOT optional (grpc reads through a LimitReader of max+1, so over-limit messages never reach EOF); a released reader is `Reset` onto an empty source (the gzip header is sender-controlled). Pool-identity tests skip under `-race`. **Both pools sit behind a ONE-SLOT warm cache** (`warmPool`): the GC empties a `sync.Pool` every cycle and the agent GCs at the tailer's flush period, so the pool missed most of the time (a miss is 17 allocs for the writer, 10 for the reader; a hit is 1). ONE slot, because a warm writer retains ~1 MiB and the steady state is serial. `putGzipWriter` Resets the writer onto nil before pooling (a `gzip.Writer` holds its sink in two places and `Close` clears neither — the slot would pin grpc's buffers; `TestPooledGzipWriterReleasesItsSink`). HTTP bodies gzip into `bufpool` buffers wrapped in a `pooledBody` whose `Close` is a NO-OP: net/http closes a request body TWICE on a redirect, before `CheckRedirect` runs and while the transport may still be reading it, and bufpool's Close returns storage to a package-level pool (`TestRedirectDoesNotDoubleReleaseTheGzipBody`); the exporter releases in `httpPost` only after EOF, and a body that never reached EOF is left to the GC. Never set `req.GetBody`.
- **Disk buffer** (`github.com/JohanLindvall/diskqueue` + `otlpexport.Buffered`, opt-in `-buffer-dir`/`-buffer-max-bytes`): a filesystem write-ahead buffer, one `Queue[[]byte]` per signal (the sink owns pdata (un)marshaling): checksummed records in preallocated segments, corruption degrading to REPORTED loss, reopen resuming from the committed cursor, flock on the dir. `OpenBuffer` sets `MaxBytes` with `MaxSegments: -1` (MaxBytes is the ONE knob) and `MaxOpenFiles: 8`. Drain: `Reserve(ctx)` → send → `Commit(offset)` after the ack; commits are a CURSOR, so a stuck head goes back via `Rewind` and rotates via `Requeue` (exempt from capacity caps since diskqueue v0.0.4 — a poison head at a full queue was a wedge). A reserved payload ALIASES the reader's buffer: hash it BEFORE any queue op. A latched I/O failure is recovered by `Buffer.recover` (guarded close-and-reopen keyed on the handle). `ErrRecordTooLarge` counts `obs.BufferFull`; every other enqueue refusal (latched I/O, closed, ENOSPC) counts `kubescrape_buffer_enqueue_errors_total{signal}` — a full disk used to go dark with every buffer metric flat. `Buffered` wraps the client with one queue per signal (generic `sink[T]` over plog/pmetric/ptrace). `IsPermanent` classifies definitive rejections; auth failures and 404 are deliberately transient (a rotating token or collector rollout must not drain the backlog into drops), as is grpc-go's synthesized `Unimplemented` for a proxy's HTTP 404 (`grpcHTTP404`). **Poison handling**: a payload whose transient rejection is really permanent (over-limit → `ResourceExhausted`) is dropped + counted after `maxDrainCycles` (3) ACCOUNTABLE failed cycles (`sink.stuckTooLong`, keyed by payload hash, bounded by `maxStuckTracked`), and an accountable lap ends after ONE attempt (`sink.accountableLap`), since a stuck head stalls every producer on the node. A cycle is accountable only when BOTH hold: the collector delivered some OTHER batch since THIS payload's own previous failed cycle (re-established every lap, never latched — latching spent the budget during pure back-pressure), AND the cycle's final error was a collector RESPONSE (`respondedError`: non-408/429/5xx HTTP, a gRPC status not on `otlpexport.RetryableStatus` — the spec's retryable list, RetryInfo-bearing ResourceExhausted included, ONE copy shared with otlpingest's relay) rather than a transport failure. So a collector rejecting everything never arms, a first sighting is never shortened, and poison costs 8 wire attempts. Tracking resets on restart deliberately; a recovered payload is `forget`-ten. **Traces are PASS-THROUGH except when OWNED** (`otlpexport/owned.go`, `Own(ctx)`/`Owned(ctx)`): a forwarded trace is still held by the pushing SDK, whose retry IS the durability; a tail-sampling DECISION acked its senders seconds earlier, so it is spooled. The marker rides the CALL, not the wiring; main opens `traces/` only under `*serviceGraphOn && TailSampling.Enabled()`; with no spool an owned payload passes through. Disk can exceed the cap by one 8 MiB segment. Occupancy is observable before loss: `obs.RegisterBufferStats` publishes `kubescrape_buffer_backlog_bytes`/`_max_bytes`/`_segments` per signal (every other buffer metric moves only once data is already lost).
- **Shutdown budgets and context seams**: every shutdown flush is BOUNDED and DETACHED — `context.WithTimeout(context.WithoutCancel(ctx), …)`, never a bare `context.Background()`, which silently strips `otlpexport.Own`. `metrics.Registry.FinalExport` takes the CALLER's ctx (`metrics.FinalExportTimeout` is the default `Run`'s own branch uses). journald's final flush is `shutdownFlushBudget` (missing it loses nothing; the cursor commits only on success). `transform.Reload`'s debounce selects on `ctx.Done()`. Both mains take their lifetime from `cli.ShutdownContext`, whose `stop` cancels WITHOUT releasing the signal handler (signal.NotifyContext's stop calls `signal.Stop`, so a SIGTERM during the shutdown that follows killed the process mid-drain). Both join their goroutine groups on the way out through `cli.WaitFor` (a stopped timer, and a spent budget still ANSWERS — a zero timer beat the goroutine observing an already-drained group and accused it of not stopping). `cmd/kubescrape-agent`'s `pipelines` carries no `ctx` FIELD — the lifetime is a parameter of every `start*` (`stop` stays, being state). `tailbuffer.Flush`'s payload is owned because `sendOwned` applies `Own` itself (`TestFlushedKeepsAreOwned`).
- **Routing** (`agent/route`, config `routing`): fans exported payloads out by `k8s.namespace.name` globs (first-match-wins, `path.Match`) to per-route OTLP clients — different endpoint and/or extra `headers` (`X-Scope-OrgID` tenancy; `otlpexport.Config.Headers` sends static headers on both transports). Composition: producers → transform → **router** → {default buffered chain | route clients}; an unmarked single-destination payload forwards untouched; only a genuine split copies. Namespace verdicts are memoised (`route/nsmemo.go`). Route destinations are UNBUFFERED by design (tenancy fan-out, not a second durability chain); a failed destination fails the whole export and the producer's retry re-splits deterministically. A payload marked `route.Reoffer(ctx)` (the producers that re-offer the same records until they land — tailer, journald, events, azurediag; `route/reoffer.go` is the roster, pinned by test) sends its route shares first and withholds the default share on a transient route failure, so a spooling default chain is not handed a duplicate per retry; unmarked payloads (single-shot producers) keep sending every share. Parts count `obs.Routed{route,signal}`. A MIXED failure returns `partialFailure`, opaque to `errors.Is`/`As` by NOT implementing `Unwrap` (it keeps `errs` and an `Errors()` accessor) and whose `Error()` FLATTENS (a multi-line body is a malformed header value and an unreadable gRPC status).

- **Tailer** (`agent/tailer`): single sweep goroutine over the configured log sources. Lines flow through `github.com/JohanLindvall/multiline`, per file: `multiline/cri` parses CRI and rejoins P/F runs (non-CRI lines pass through), then `multiline` joins stack traces. Offset mapping relies on synchronous stage emission inside `Add`/`Flush*`: `lastEnd[key]` is exact, and `Entry.Lines` (multiline ≥ v0.0.11 charges cap-dropped lines to the last emitted entry, so `sum(Lines)` equals lines consumed — pinned upstream) pops the per-key FIFO of offset ranges. The pre-v0.0.11 compensation machinery is DELETED, so an upstream regression no longer self-heals: an UNDERcount leaves orphan FIFO items that wedge the file's watermark, and an entry emitted with an empty FIFO is dropped un-exported, counted `kubescrape_log_entries_unmapped_total` with a throttled Warn (`traceEmitFunc`) — the contract is the library's. A never-completing group is force-flushed once its FIFO passes `maxGroupBuffered` (`boundGroup`); an endless CRI P-run is bounded by consumed bytes in `feedLine` (`streamState.runBytes`; `forceFinal` rewrites the crossing fragment's tag to F). **At-least-once**: exports are inline with retries; offsets commit only after a successful export and never past buffered lines (`watermark` = min of `runStart` and FIFO heads); a TRANSIENT failure rewinds to the committed offset and discards the pipeline unemitted; a PERMANENTLY rejected batch (`otlpexport.IsPermanent`) is the one LOSS path — dropped and offsets advanced (`advanceBatch`, not `commitBatch`), counted `kubescrape_log_permanent_dropped_total` + an Error — **the tailer's data-loss signal, alert on any nonzero rate**. With `-buffer-dir` Export returns the ENQUEUE verdict, so that counter moves only for a batch over the whole cap and the collector's rejections land on `kubescrape_buffer_dropped_batches_total{signal="logs"}` + `kubescrape_buffer_dropped_records_total{signal="logs"}`. Checkpoint PRUNING is gated on a successful listing (`lastListingOK`), and so is the END OF STARTUP: stored positions are consulted by EVERY scan (a failed startup glob would otherwise re-ingest the node from byte 0 with no counter moving); an entry is consumed when applied and dropped when a SUCCEEDED listing did not see it; `-logs-unknown-files` (auto/end/start; auto = start when the store has entries) governs a checkpoint-less file only while its SOURCE starts up (`compiledSource.startingUp`); a positions file that failed to DECODE reports `Corrupt()` so `auto` re-reads. Positions persist immediately on discovery and on segment recording. Metadata is resolved before any data is consumed (server-side wait; exponential backoff 2s→1m, jittered `[d, 1.25d)` — the lookup runs on the single sweep goroutine and an unjittered fleet recovers in one burst); a file deleted before resolving counts `obs.LogUnresolvedLost`; an unresolved file is `kubescrape_log_files_unresolved` + an age-gated throttled Warn; the sweep's resolve budget counts `kubescrape_log_metadata_budget_exhausted_total` once per sweep (separate throttles — the two co-occur). Idle files close their fd after `-logs-idle-close` (0 = never; reopen stat-gated with identity re-verified; eligibility compares `fedEnd()` to `committed`); a rotation landing while no fd is held is recovered by `ensureOpen`'s replaced arm as an open-ended segment (a same-inode head mismatch is an in-place rewrite: no segment). **Rotation**: identity = inode + head fingerprint (FNV of the first `-logs-fingerprint-bytes`; catches inode reuse and copytruncate; a PRE-read re-verify in `readFile` when mtime moved catches a LONGER replacement; fingerprints EXTEND only while the hashed head still matches, from `saveCheckpoints` AND `readFile`); the truncation decision uses how far the pass READ, not the rewound readPos, and every truncation arm re-opens immediately; a rewound pass leaves `lastMod` unstamped so the pre-read re-verify still fires; rename rotation drains the old fd and opens the new incarnation IMMEDIATELY (a second rotation in the window would otherwise lose the middle incarnation); deletion drains before drop. **Segment-qualified offsets**: every offset is `pos{seg, off}` with `seg` a per-file monotonic incarnation id; each rename closes the tail into a `segment` `{id, inode, fp, committed, to, fd}` on `file.segments`. `to` is the last FED line boundary, not readPos (never-fed trailing bytes can never commit). An unrecoverable segment is counted (`obs.LogPrefixLost`) AND retired. A drain that does not reach the end completes the rotation with an OPEN-ENDED segment (`to = -1`, `fedTo` at the drain boundary) replayed by `feedSegments` under `MaxBytesPerSweep` — for a mid-drain flush failure and for the per-drain cap (`defaultDrainCap` 1 GiB, a bound on one call, never on what may be recovered; it used to lose everything past it silently). A gone file's unfinished drain does not stamp `goneEnd`. Accepted cost (`drainReader`): while a replay is unfinished the live tail is not read. An entry commits against `end.seg`'s record; a segment retires when its whole range commits; a dead id resolves to nothing. **Multi-line groups join across a rename rotation** (`reopen` carries the pipeline). Incomplete segments are checkpointed (`positions.Prefix`, `From` = commit progress; an oversized line's discard progress persists on the segment, `skipTo`/`discarding` (zeroed with `fedTo` by `purgeSegmentFeeds` on any discarding pipeline rebuild, never by `reopen`'s drained one), so a replay does not resume at the same offset until the stall limit retires it; `chargeStall` counts discard as progress; a gone file's drain shares the stall budget via `chargeGoneStall`, so a regressing error boundary retires the file loudly instead of wedging its fd). Retained fds are CAPPED (`maxCarriedFds`, oldest pruned first); `reopen` never resets `segments`; after a restart `feedSegments` re-reads each owed range under its own id, with `findRotated` (inode+fp in the resolved target dir) as the fallback, counting + retiring when that fails; a rotation while DOWN is recovered by `initFile` synthesizing an open-ended segment. Caveat: the join spans only rotations the tailer OBSERVED. Truncation/copytruncate flush-and-reset. Audited micro-edges, all fail-safe and none worth code: an `end`-mode skipped file checkpoints inode 0 until its first read, so a crash there plus a rotation-while-down into a longer file can resume mid-file; `LogTornFinalLines` counts rename rotations only; `LogBytes` excludes segment-replay re-reads. Pause mode's no-loss contract holds across every restart path (`file.restartAt` clears `limited`/`discarding` with pending everywhere). An unterminated fragment at a rename rotation whose drain reached the end is dropped counted (`obs.LogTornFinalLines`, gated on `drained && !f.discarding`); an oversized unterminated line (> MaxEntryBytes+4096) discards prefix and remainder (`file.discarding`, `obs.LogOversizedDropped`). **Status** (`status.go`): `publishStatus` every 10s → `Tailer.Status()` → `GET /debug/tailer`; `kubescrape_log_sweeps_total` is the sweep goroutine's HEARTBEAT (the gauges freeze when it wedges); `kubescrape_log_lag_max_bytes` per-file max, `kubescrape_log_lag_bytes` the sum; compressed files report `Lag = ReadPos − Committed`. **Withheld commits**: a record exported while another stream's group is buffered has its commit clamped to the build-time watermark; the high position is remembered per segment (`file.exportedHighs`) and re-offered at the next flush — and **a REWIND DROPS THEM**, because a rewind reuses the tail id and a stale high committed a truncate-and-rewrite replacement past bytes never exported; `ensureOpen`'s in-place-truncation arm takes the same new-incarnation path as `replaced` and counts `kubescrape_log_rotations_total`. **Observation is once per RECORD, not once per PASS**: a failed export rewinds and re-reads (at-least-once), but log-derived metrics and `kubescrape_log_rules_dropped_total` are CUMULATIVE, so `file.observed` (bounded by `maxObservedEntries`, keyed by `obsKey` = segment-qualified byte range + a BODY hash — load-bearing, since a rewind then truncate-and-rewrite reuses the same offsets in the same segment) carries `logchain.Input.Observed`, which suppresses the COUNTING half only. Recording happens AFTER the export outcome, never before (`TestRateDroppedLineAdmittedLaterIsStillObserved`). Exports are synchronous in the sweep (`flush.go`: `batchInfo` → `commitBatch`/`failBatch`); the pipelined-export mode was REMOVED (`-buffer-dir` provides the decoupling; docs/tailer-comparison.md). `failBatch` narrates an outage like the apiserver watchdog: transition, throttled repeat, `log export recovered` once.

WELFORD (catastrophic cancellation on a large mean with small variance — exactly the CPU case), POPULATION stddev (what Prometheus' `stddev_over_time` computes; pinned to 1e-12 in-repo). Three rules: **identity is rebuilt PER EXPORT through the same `Scraper.FillContainerResource` the cadvisor batcher uses** (byte-identical to the cadvisor row's, pinned by fixture; caching it for the container's lifetime made the two diverge on an in-place label edit); **an UNRESOLVED container is not exported at all** (a cgroup path yields no pod NAME, so there is nothing to fall back to and a series with no `job` cannot join — which also keeps the pod SANDBOX out); **a sparse window holds the last value at most twice, per signal**, while a vanished container flushes its final window for real and retires (an OOM-killed container's last burst is the case the feature exists for). cgroup v1 DISABLES this pipeline alone and logs an ERROR (a node property must not take the log pipeline down across a mixed fleet), even at an explicit `-cgroup-stats-root` holding a GENUINE v1 hierarchy (no hierarchy, or no `memory` controller, stays fatal). Needs the node's `/sys/fs/cgroup` read-only BESIDE the container's own, never over it (`internal/cli` reads its memory limit there): the chart mounts it at `agent.cgroupStats.root` behind `agent.cgroupStats.enabled` and renders `-cgroup-stats-root` to match, `deploy/agent.yaml` carries flag, mount and volume commented out together, and an enabled agent finding no pod cgroups WARNS periodically and publishes `kubescrape_cgroup_containers` at 0 — registered exactly when the sampler runs, so 0 means "on and finding nothing", never "off".
- **journald** (`agent/journald`, opt-in `-journald`, **cgo**): reads the journal natively via `go-systemd/v22/sdjournal`. Deliberately IN scope: node/system LOGS (kubelet, containerd, systemd units) are how a node's Kubernetes plane is debugged and often live only in the journal; host METRICS are not. **The mount requirement is TWO things**: `/run/log/journal` (volatile) and, for the PERSISTENT journal under `/var/log/journal/<id>`, the node's `/etc/machine-id` — with `SD_JOURNAL_LOCAL_ONLY` libsystemd reads only the container's own machine-id directory, so without it the reader blocks exporting nothing with no counter moving (kind is volatile-only, so e2e cannot catch it). The chart mounts both behind `agent.journald.enabled` (`type: File`, never FileOrCreate — an empty machine-id fails the same way; `journaldmount_test.go` pins the pair) and `journalfiles.go`'s startup probe MODELS the gate (`machineGate`), naming the two remedies apart. journald is the SOLE reason the agent is cgo/non-static (`distroless/base` + copied libsystemd and its six deps); behind the `journald` tag, `TAGS=azure,events` yields a static agent (`journald_disabled.go` simply does not import this package). One resource per unit; the reader is behind a `source` interface (`source_sdjournal.go`; tests inject `fakeSource`), so every other file (`journald.go`, `convert.go`, `sanitize.go`) has no cgo. An over-`MaxEntryBytes` message is truncated on a rune boundary with `log.truncated` + `log.original_length` (`logchain.AttrTruncated`/`AttrOriginalLength`), counted `obs.JournalTruncated`. Seek: `SeekCursor` + skip the cursor entry once, or `SeekTail`+`Previous`; at-least-once via the cursor, committed after export (persisted at most every 10s; a hard kill replays that). A READER error reopens from the committed cursor with backoff; an EXPORT failure does NOT — `flushRetry` retries the SAME payload in place, counting `kubescrape_journal_export_failures_total` (attempts, not lost entries), because rebuilding re-runs the per-record chain and multiplies log-metric observations. Delivery is at-least-once; OBSERVATION is once per delivery. The retry is unbounded on purpose (the batch is bounded, the journal is the buffer behind it, a genuinely undeliverable payload is the PERMANENT case `flush` settles); this SUBSUMES the old cursor-less-first-run special case, since an empty cursor reopens at the TAIL and no batch may be discarded. `-journald-flush-interval` is measured from the LAST FLUSH (`ticker.Reset`; the old form delivered at 2x the interval). `kubescrape_journal_entry_defects_total{defect}` covers the two invisible read-side repairs, invalid_utf8 and no_timestamp (only surviving bytes probed; an unknown PRIORITY is visible in the severity field and not counted). `Run` logs `start=tail|cursor` — with no stored cursor everything already in the journal is never exported.
- **Kubernetes events** (`internal/agent/events` + `internal/leader`, opt-in `-events`, behind the `events` build tag): a CLUSTER-SINGLETON pipeline — the agent binary as a single-replica Deployment (`templates/events.yaml`, `deploy/events.yaml`) with every per-node pipeline off, NOT in the DaemonSet (cluster-wide `events` read plus lease/configmap write on every node, and one Lease poll per node). Its namespaced Role scopes `get`/`update` on the position ConfigMap and the Lease with `resourceNames` (`create` unscoped — RBAC ignores `resourceNames` there), so code execution in the events pod cannot rewrite the agent-config ConfigMap; `internal/chartcheck` asserts the names track `-events-lease`/`-events-position-configmap`. `leader.Run` wraps client-go `leaderelection` in a re-entry loop (its `Run` returns on loss and never re-acquires; callbacks are async, so an `acquireLatch` on the resource lock latches acquisition SYNCHRONOUSLY, `elect` joins the work goroutine, and the leading gauge reports down only after the join). `Reader.Run` batches → exports → and only after the ACK advances and persists the position. **The position is a ConfigMap** (`ConfigMapStore`) because the leader moves; a written position is a LOWER BOUND on what was delivered, so a zombie writer is harmless and no fencing is needed. Position = watch `resourceVersion` + timestamp `Watermark`; past the watch window the watch fails Gone and `expire` arms `relist`: a PAGINATED LIST (`replayBacklog`, 500/page, watermark-filtered) secured by a fact THIS PROCESS observes (last page read, every entry exported), never a BOOKMARK (kube-apiserver sends none for core/v1 events, so the old `secureReplay` hold was permanent). The walk's count trigger is clamped to the retained-batch cap and its tail flushes BEFORE the watch opens (unclamped, the backlog shed into `obs.EventsOverflowDropped`); a failed export mid-walk WAITS, retrying in place (`exportUntil`). While UNSECURED, `settle` HOLDS the position (`heldWatermark` accumulates) because the backlog arrives in STORE order and committing a rendered prefix's maximum lost lower-RV backlog; a death mid-replay costs a full re-replay. A redelivering stream (committed resume, relist, cold `start`) DROPS the retained batch first; only the cold skip-backlog path retains; a cold `-events-start=end` expiry honours the start mode. A BOOKMARK applies immediately only when the batch is EMPTY. `Modified` IS an occurrence (aggregated `count`); `Deleted` is TTL expiry, ignored. The RESOURCE is the INVOLVED OBJECT's (a Pod via `metaclient.PodByName` with UID cross-check, so a recreated pod cannot lend its identity to its predecessor's event) — that is what makes events correlate with the pod's logs; a non-resolving pod is exported under the event's identity and counted `kubescrape_events_unresolved_total{reason}` (lookup/uid_mismatch) with a throttled Warn, since the failure has no other symptom (lookups, on the only goroutine, are bounded at 2s and pause 30s after a timeout; a failed resolution is memoized 30s (`unresolvedRetryAfter`), not for the batch, and its records group apart from resolved ones); `actx.Node` is NIL. Full chain in the tailer's order; `-events-position-interval` bounds REPLAY after a hard kill (a graceful stop writes a final position from a detached context).
- **Azure diagnostics** (`internal/agent/azurediag`, opt-in `-azure-diagnostics`, behind the `azure` build tag): consumes diagnostic-settings output (resource logs AND platform metrics) from Event Hubs over KAFKA (franz-go, 9093, TLS). Same singleton Deployment as `-events` (either section's `enabled` creates it) but NO leader election: the consumer-group protocol IS the coordination and the committed offsets ARE the position (replicas > 1 share partitions). Ack-gated at-least-once: `source.commit` runs only after BOTH signals ack (`Reader.deliver`); a permanent rejection or undecodable message is counted and committed past (poison must not wedge the partition); a transient failure retries in place. kgo sits behind the journald-style `source` interface; `kafka_test.go` runs a real group against `kfake`. **A connection string may be NAMESPACE- or ENTITY-scoped** (`parseConnectionString`: case-insensitive keys, each part cut at its FIRST `=`): an `EntityPath` names a hub AND bounds the credential, so `Resolve` makes it the topic when none is configured (`applyEntityPath`) — the `^insights-.*` default is a PATTERN that matches no entity named otherwise (the consumer then reads no topic, indistinguishable from a quiet hub) and requests namespace-wide metadata the credential may lack. Explicit `-azure-eventhub-topics` win; a list omitting the entity WARNS. **Several hubs = one client per CREDENTIAL** (`sources.go`, `ResolveSources`): both `-azure-eventhub-namespace` and `-azure-eventhub-connection-string-file` take comma lists; N entity strings are N Readers (own client, offsets and gate, named `azure-eventhub[ns/topics]` when more than one); more than one namespace beside connection strings is REFUSED (`validateAzureFlags`, file-free); duplicates refused. **Groups are auto-disambiguated** (`disambiguateGroups`): a namespace holding more than one client gives each `<group>.<topics>`, because the group LEADER assigns from its OWN metadata and starves the hubs it cannot see; growing a namespace from one client to several therefore renames the first's group and restarts per `-azure-start`. The password is the string VERBATIM — stripping `EntityPath` is the wrong instinct (scope follows the rule the key was created on). **Auth** (`auth.go`): connection string → SASL PLAIN (file re-read per session); managed identity → OAUTHBEARER with a hand-rolled Entra token source (workload identity's client_assertion when `$AZURE_FEDERATED_TOKEN_FILE` + client/tenant exist, else IMDS; cached, refreshed `refreshMargin` early, stale-but-valid served on failure, failed fetches backed off by `tokenRetryBackoff` — never past the token's own expiry — because `get` runs per SASL session under one mutex; lines throttled). The cached token is DROPPED when the consumer is rebuilt (`KafkaConfig.Invalidate`, set by `Resolve` on the MI path, called by `Run` before reopen): the rebuild is the recovery for `fatalFetchErr` (group/cluster authorization, unwrapped from `*kgo.ErrGroupSession`), and a cached token would be re-presented for ~55 minutes after an operator fixed the role. No Azure SDK (the OAuth2/SigV4 trade). **Decode** (`decode.go`): `{"records":[...]}` walked with lightning `ArrayEach` (≥ v0.0.62, STRICT); one `GetPaths` pass per record; classification per RECORD (`metricName` + ≥1 aggregation → metric). Logs keep the verbatim record JSON as body and run the full chain (`resultDescription` scrubbed too). Enrich's `cloud.resource_id` and `azure.resource_group.id` are ELIDED per record (`redundantOnAzureResource`, after the chain, gated on the resource having identity) because the converter is authoritative from the envelope's own `resourceId`; `azure.category` (envelope) and `azure.event_category` (body) are different fields and stay. The `.id` suffix is deliberate: semconv defines only `azure.resource_group.name`, and a bare key would sit one dot from it with a different shape. Metrics become GAUGES `<prefix><metricname>.<agg>` (count/total/minimum/maximum/average, `azure.metric.timegrain` dp attribute) — closed pre-aggregated windows, not delta (Mimir rejects it) nor cumulative (per-series state). The ARM resource is the OTLP resource (`resourceid.go`): `cloud.resource_id` verbatim, subscription/rg/type/name lowercased, `service.name` = resource name, `service.namespace` = resource group, `service.instance.id` = lowercased id. Readiness gate `azure-eventhub` clears on the first poll. A call into this package from an UNTAGGED file re-links franz-go into every variant — `make verify-tags` catches it.
- **Log enrichment** (`agent/logenrich`, ONE flag `-enrich`, default true, covering the tailer, journald, the events and azurediag converters and the ingest log path alike): `logenrich.Apply(lr, line)` runs `github.com/JohanLindvall/enrich` over each exported line (events and azurediag use the OVERWRITING `Apply` like the tailer; ingest uses `ApplyBodyText`, the sender being authoritative). A parsed timestamp overrides the CRI/journal time ONLY when it carries its own zone (`enrich.Result.TimeHasZone`); a zone-less one is an ambiguous wall clock that enrich reads as UTC, so a `TZ=`-configured workload would be misdated by the offset — the producer time is kept and counted `obs.LogEnrichTimeRejected`. With no producer timestamp at all (plain-file and ingest paths) either is taken. Explicit level overrides severity (enrich's severity numbers ARE the OTLP numbers), 32/16-hex IDs (dashes stripped, all-zero rejected) fill the trace/span fields, the rest become record attributes (`log.template`, `exception.*`, `azure.*`, `cloud.resource_id`). `exception.stacktrace` is suppressed for `Format == pattern` (a pattern-parsed trace is a verbatim slice of the body — the attribute would double megabyte multiline entries; JSON-carried traces stay, and a substring check does NOT work). `Result.Format` feeds `obs.LogEnriched{format}` ("" → "none"). Body is never modified. New log-exporting paths should call `Apply` behind a config toggle.
- **One log chain, one resolver** (`internal/agent/logchain`): the key resolver every log producer needs — record attributes first, then the resource (the `attrs.ReservedIdentity` keys the other way round: identity is a resource concern, so a record's `k8s.namespace.name` must not satisfy a namespace allowlist or forge a label), with the synthetic `__severity__` for RULES only — plus `LowerSeverity`, live in ONE place. There were five copies (tailer, journald, events, azurediag, `-test-config`) and five spellings of the severity lowering, of which only the tailer's handled `WARNING`. The tailer's per-line budget is unchanged (closures still bound once). `Input.Observed` is the producer's assertion that an EARLIER pass over the same bytes already counted them; it gates EVERY counter whose unit is a RECORD, wherever the increment lives — `LogMetrics.Add`, `obs.LogRulesDropped`, and the `logenrich` pair `obs.LogEnriched`/`obs.LogEnrichTimeRejected` (which is why `Emit` reaches enrichment through `ApplyUncounted` on that branch; `sum(kubescrape_log_enriched_total)` is read as the decomposition of `kubescrape_log_entries_total` by format) — and `obs.LogScrubbed` (`Line(body, observed)`). `chain.go`'s `Input.Observed` comment is the authoritative list, and `Config.CountsRecords` is its predicate (a producer gating its proof on a hand-written copy left enrichment out). Only a producer holding POSITIONAL PROOF may set it — the tailer via `file.observed`, the events reader via `obsKey`/`wasObserved`; journald never needs it, having stopped rebuilding. Under-claiming re-counts (merely inflated); over-claiming destroys observations (invisible) — when in doubt, do not claim.
- **…and one RECORD-BUILD LOOP** (`logchain.Chain`/`Producer`/`Input`, `chain.go`): scrub → lift line attributes → stamp → enrich → log-metrics → keep/drop rules, in that order, was a fourth copy in each of the same producers. `Chain.Line` does the two steps that must precede GROUPING (scrub, extract) and hands back the resource/scope halves the caller groups on; `Chain.Emit` runs the rest and returns whether the record was KEPT (a false return still advances offsets/cursor; the drop is already counted). Budgets: BenchmarkIngestLine 0 allocs/op, BenchmarkIngestFlush 4/4/5/12 per line (plain/enrich/enrich+metrics+rules/enrich+lift, whatever the `-benchtime`), ENFORCED per shape by `TestIngestFlushAllocationBudget`.

- **PII scrubbing** (`agent/logscrub`, config `logScrubbing`, shared by every log producer — tailer/journald/events/azurediag via `logchain.Config.Scrub` — and ingest): curated built-in patterns (`builtin: [defaults]` = bearer/basic-auth/secret-kv/aws-key/private-key/url-userinfo; `email`/`credit-card` opt-in by name — `defaultSet` is the AUTHORITATIVE list, and `TestDefaultSetIsDocumented` pins this file, README and CONFIGURATION.md, because the prose said "five" for as long as it had six) plus user regex rules, applied to log BODIES **before** logattrs/enrich/log-metrics copy from them. Every built-in carries a prefilter so the no-match path is 0 allocs. **A prefilter's job is to admit only what the regex can MATCH, not what contains its keyword**: `secret-kv`'s scanned for bare keywords anywhere, and a 1 MiB record containing "token" cost 100 ms of the SINGLE sweep goroutine — `secretKVCandidate` now checks the regex's own tail shape in one pass with a first-byte dispatch. **The no-match path is a per-BYTE cost, so it is measured per byte** (`bench_test.go`: a 350-byte JSON line, an `@`-bearing line — every image digest has one — a redacted line, a hostile 1 MiB line). `asciiIndexFold` (the "bearer" and "basic" prefilters) takes its candidate positions from `strings.IndexByte` on BOTH cases of the needle's first byte, with TWO CURSORS so each case is scanned at most once (a per-candidate restart is quadratic on a megabyte of `b` followed by one `B`); `kvStart`, a 256-byte gate derived from `kvDispatch`, replaces loading a slice header per byte (`TestSecretKVDispatchDerivation` is a security pin). `asciiIndexFold` IS those two prefilters, so it is pinned against the naive walk as the DEFINITION (exhaustively over a case-adjacent alphabet, over random inputs, and by `FuzzAsciiIndexFold`). A prefilter must stay a strict SUPERSET of the regex — narrower means a secret ships unredacted (`TestPrefilterIsNotNarrowerThanItsRegex`, `TestSecretKVPrefilterCoversEveryMatchingShape`, `FuzzBuiltinPrefiltersNotNarrower`; Go's `\s` does NOT include `\v`). Unknown pattern names and bad regexes fail startup. Counts `obs.LogScrubbed{pattern}`. Log-metrics see the SCRUBBED line. The value branches decode ONE level of escaping, and the plain and escaped forms use OPPOSITE rules for `\"` — inside `\"…\"` it TERMINATES, inside `"…"` it is CONTENT — selected by the opening quote, escaped pair tried first: the fix for `password=[REDACTED]"hunter2\"`, a line that CLAIMS a redaction and still carries the secret, which the counter cannot distinguish from a clean one. `url-userinfo` redacts to the LAST `@` in the token (`svc:p@ss@db-1`). What remains PARTIAL is pinned (`TestKnownPartialRedactions`: an unquoted value containing its own delimiters, more than one level of escaping), as are the accepted OVER-redactions (`TestKnownOverRedactionsAreAccepted`); `TestQuotedCredentialsAreRemovedWhole` is the cross product that keeps the guarantee from being asserted over a corpus curated around its holes. LIMITATION: per-record, so a multi-line PEM key logged line-by-line has only its BEGIN line redacted.
- **Log-line attribute lifting** (`pkg/logattrs`, config `logAttributes`, shared by `-logs` and `-journald`): ordered rules map a JSON/logfmt key to a resource/scope/log attribute. JSON is scanned once for all rule paths via lightning `GetPaths` (dotted keys descend); logfmt via the `logfmt` reader; do NOT reintroduce `encoding/json`. **`key= value` reads as an EMPTY value** since logfmt v0.0.10 (go-logfmt's reading; earlier versions read `("key","value")`), so a line written that way lifts an empty attribute and mints an empty label in `internal/logline`. `Iterate` yields RAW values (quotes stripped, escapes intact): unescape with `AppendUnescape`, guarded by `NeedsUnescape`, only for a QUOTED value (`logattrs.LogfmtValueView`). Resource/scope attributes participate in the flush grouping key (`logGrouper` in the tailer, the `unit\x01res\x01scope` key in journald `convert`); log-target attrs go on the record. Typed: integer tokens → PutInt (int64; past int64 → double), whole floats → PutInt only inside ±2^53 (`storedAsInt` — past it a whole double is only the nearest representable value, and stored as an int it would read differently from the label path's rendering), else PutDouble; bool → PutBool.
- **Unified positions** (`agent/positions`, flag `-positions-file`): one JSON file holding the tailer's per-file `LogPos` map and the journald cursor; the `Store` rewrites the whole doc atomically under a mutex, so the two sections never clobber each other. It is the ONLY offset persistence (the legacy `-checkpoint-file` was removed); the tailer's `checkpoint` type is a `positions.LogPos` alias; journald has no standalone cursor file (without a store it starts at the tail). `Open` logs its lifecycle: a first run says so explicitly (with no stored positions `-logs-unknown-files=auto` resolves to `end`, so every existing file is skipped to its end — the most common "the agent is collecting nothing" report), a resume reports COUNTS only (never paths, never the cursor), and a temp-sweep that cannot delete Warns, the earliest evidence that every save will fail.
- **OTLP ingest** (`agent/otlpingest`, opt-in `-ingest`): a gRPC (`:4317`) + OTLP/HTTP-protobuf (`:4318`) receiver for LOGS AND METRICS apps push to the local agent. **TRACES ARE NOT HERE** — the `-service-graph` tier receives them (pairing and sampling need every span of a trace in ONE process); `ServerConfig.Exporter == nil` disables logs/metrics (the tier's traces-only mode), `Traces == nil` disables traces, so a mis-aimed sender gets Unimplemented/404 rather than an ack for telemetry nothing will use. `ServerConfig.Ready` fires once every listener is BOUND. `Enricher` finds a container id (`container.id`/`k8s.container.id`, configurable) or `k8s.pod.uid`, resolves via `metaclient`, and merges the `Builders.Ingest` attributes with the sender authoritative about ITSELF — **except the RESOLVED-IDENTITY keys** (`Enricher.resolvedWins`: `attrs.ReservedIdentity` minus the lookup keys of the kind it resolved by, minus `senderControlledIdentity`), which OVERWRITE the sender's claim: `route.match` keys tenancy on `k8s.namespace.name`, so on a resolvable resource a forged one cannot reach the router. Metrics mode (`-ingest-metrics-mode`): `resource`, `datapoint` (`split.go` regroups points into per-object ResourceMetrics, all 5 types; id-less points fall back to the resource id), `auto` (splits only when a point names another object than its resource; the splitter MOVES points, so use `EnrichMetrics`' return). Two strips, two EVENTS: identity counts `obs.IngestIdentityStripped{key}` at DEBUG (every conformant SDK names its own pod, so this is not an alert), plumbing (`route.ScriptMarker`/`DropMarker`) counts `obs.IngestReservedStripped` with a Warn. Three exclusions: `service.name` (descriptive — naming its service is the point of a sender); `service.namespace`/`service.instance.id` (`senderControlledIdentity`; kubescrape reads neither, and `resolvedWins` exempts the SAME two — briefly it did not, and every resolved sender's job was renamed and its instance pinned to a per-restart container ID); and the LOOKUP KEYS (stripping what attribution is MADE BY resolves nothing; both kinds are kept). **RESIDUAL, documented not closed**: `/v1/pods/{ns}/{name}` is unauthenticated and the container index cluster-wide, so a pod can read a victim's `container.id`, push it declaring nothing, and have the victim's namespace DERIVED for routing — nothing forged, so no counter moves. Refusing off-node objects would cost legitimate attribution (split path, tier, Service-fronted receivers) without closing it; what closes it is authenticating a listener. `TestStolenLookupIDStillResolvesTheVictimsNamespace` pins the current answer. The COST: an unresolvable sender loses its honestly-declared Kubernetes half and keeps its service triple; one resolved only at POD grain loses its container names. Payloads forward as received — NO agent-side batching (an earlier `otlpbatch` layer was the only layer that traded a guarantee away). **The operator's cost levers reach pushed logs** (`logchain.go` here: `ServerConfig.Scrub`/`EnrichLines`/`Rules`/`LogMetrics`/`LogAttrs`, the producers' `logchain.Config` set; `EnrichLogs` is resource-only): the scrub runs first on every whole body; after enrichment, records run the same rules, feed the same set and take `logAttributes` lifts IN PLACE through the same primitives (only the `target: log` half is WRITTEN — a resource lift is applied by GROUPING and a pushed record lives in the sender's grouping — while the resource half still RESOLVES via `SetLifted` and the scope half is dropped). Metrics observe before rules; a dropped record is ACKED (`obs.LogRulesDropped`); an all-dropped payload acks without a send. **The counting units DIVERGE here, the ONE place they do**: a log-metric observation and `obs.LogScrubbed` are per RECEIVE ATTEMPT (a NACKed push re-runs the chain), `obs.LogRulesDropped` per DELIVERY — there is no positional proof to hang `Input.Observed` on. Line enrichment runs HERE too (`logenrich.ApplyBodyText`) over ONE bounded text rendering per body (a STRUCTURED body renders via AsString with its size ESTIMATED first); `__severity__` falls back to the severity-NUMBER band (`logchain.RecordSeverity`). Sender-bounded (`obs.IngestChainSkipped{reason}`; data forwarded, rules still run): a body over 1 MiB is read on its first 1 MiB, a structured resource value renders once (`resourceTextView`) and one whose text exceeds 64 KiB resolves empty (`resource_value_too_large`), resources wider than 64 attrs or past the first 256 skip metric observation; duplicate resource KEYS are deduped last-wins BEFORE enrichment when rules or logMetrics are configured. Counts `obs.Ingested{enriched,unresolved,peer_ip,peer_ip_rejected,split_capped}`. **A pushed metric with NO data points dies at receipt** (`emptymetrics.go`, after the admit hook, before the all-rejected check; counted `kubescrape_ingest_empty_metrics_dropped_total` + throttled warn): legal OTLP nothing downstream rejects, spending framing on every push; kubescrape's own producers cannot emit one (`internal/pdatacheck.EmptyMetrics` keeps that honest; `transform`'s `pruneDataPoints` and `cumagg.Store.Render` drop emptied shells). **Splitter memory is bounded separately** (`maxSplitGroups`; each group copies the sender's resource, so cost scales with data-point count; past the cap the remainder folds into ONE identity-stripped overflow resource per input, `split_capped`, as do mid-push byte-budget refusals even for an already-grouped id). **Concurrency is BOUNDED** (`-ingest-max-in-flight`, `defaultMaxInFlight` 32, also `grpc.MaxConcurrentStreams`): over the bound `acquire` refuses WITHOUT waiting and RETRYABLY — HTTP `429` + `Retry-After: 1`, gRPC `ResourceExhausted` **with `errdetails.RetryInfo`** (without it conformant senders drop the batch, and a shed that loses data is worse than the OOM it prevents). **Memory is bounded SEPARATELY from the count** (`admit.go`, `byteBudget`, `maxBufferBytes` = 4 × the 16 MiB body cap, a floor `-ingest-grpc-max-recv-bytes` raises only once 4× it exceeds 64 MiB; the flag also applies to the tier's application ports): the count cannot bound BUFFERING — HTTP handlers read the whole body BEFORE taking a slot (the acquire must not move back before the read), grpc-go decodes before the interceptor. An HTTP body is charged as READ (`budgetReader`) and pre-sized from a BOUNDED head (`maxPresizeBytes`), never from `Content-Length`; a gRPC push reserves `MaxRecvMsgSize` in `grpc.InTapHandle` (the only pre-decode hook), released by the FIRST of the interceptor, the stream ctx's `AfterFunc`, or the DECODE WINDOW elapsing (`reserveWindowFor`: 10s at 4 MiB, scaled with the flag, ceiling 5 min; a headers-only stream reaches neither of the other two, and sixteen of them pinned the budget for the process' life). Expiry counts `kubescrape_ingest_reserve_expired_total`, separate from `obs.IngestRejected`. **A THIRD budget bounds what raw bytes INFLATE INTO** (`decodedBudgetFactor` = 2× the raw one): a 16 MiB body of minimal ResourceLogs inflates 16x, and four are admitted. Its estimate is read off the WIRE and charged BEFORE the decode (`decodedsize.go`; the gRPC codec leaves a refused message undecoded, and `claimReaper` — a stats handler `admissionOptions` wires as ONE unit with the tap, interceptor and codec — returns the claim of an RPC that ends before the interceptor, since a unary `RecvMsg`'s cardinality probe can fail after the decode), down to each KeyValue, not strings (bounded transitively). A single push whose structure alone exceeds the budget can never be admitted and gets the same retryable refusal plus a once-a-minute warn. Refusals count `obs.IngestRejected{reason}` (`in_flight`, `buffer_bytes`, `decoded_bytes`); the throttled shed line names `-ingest-grpc-max-recv-bytes` only when it raised the budget (`budgetSourceArgs` — at the floor it says to shrink sender batches, since the flag cannot move the limit there). **A body's SHAPE is refused before the decode** (`depth.go`, `maxNestingDepth` 100; `checkNesting` via `BodyReader` on HTTP and `NestingGuardOption` on gRPC, hooking the CODEC): pdata's decoder recurses without a limit, so ~1.6 MiB of nesting peaked at 128 MiB of stack; the walk is O(len), allocation-free, schema-less; the refusal is PERMANENT (400 / Internal) and counts `obs.IngestBodyRejected{too_deep}`; the tier's internal receiver takes `NestingGuardOption(nil)`. **The HEADER block is bounded** (`maxHeaderListBytes`, 64 KiB, BOTH transports: `MaxHeaderListSizeOption` on every gRPC listener including the internal port — decoded before the budget tap, the auth tap and the depth guard, at a 16 MiB default — and `NewPushHTTPServer`'s `MaxHeaderBytes`, 431 before any handler, at net/http's 1 MiB default; per connection, not in total — the HTTP connection count is an accepted residual). Attribution WAIT is bounded per push (`lookupWaitBudgetFactor`: at most 4×`-ingest-metadata-wait` total by elapsed time; `maxLookupsPerRequest` bounds count only).
- **Span metrics** (`agent/spanmetrics`, opt-in `-ingest-span-metrics`, on the `-service-graph` TRACE TIER): RED metrics derived from received spans, following the OpenTelemetry spanmetrics conventions — a monotonic `traces.span.metrics.calls` counter, a `traces.span.metrics.size` byte counter, and a `traces.span.metrics.duration` histogram (seconds, with per-bucket trace-id **exemplars**), dimensioned by `service.name`/`span.name`/`span.kind`/`status.code` plus configurable extra span-then-resource attribute keys (`traceMetrics` config: `namePrefix`/`buckets`/`dimensions`/`maxCardinality`/`exemplars`). Each span aggregates INDEPENDENTLY, so the cumulative counters sum across shards — and the tap runs on the OWNING shard only (inside `buildOwnerChain`), so a span that took the re-shard hop is counted ONCE. It is a `TracesExporter` **tap** (`Generator.Tap`) wrapping the raw exporter: it sees enriched spans, forwards FIRST and aggregates only on success (a transient failure surfaces retryable to the application, whose re-push must not double-count). Consume runs on the concurrent receiver goroutines (series map mutex-guarded); the batch is forwarded UNCHANGED. A **self-contained cumulative aggregator** on `internal/agent/cumagg`, NOT `metrics.Registry` (exemplars are a histogram-data-point feature the Registry cannot express). A **cardinality cap** (`maxCardinality`, default 20000; a new tuple over it is dropped and counted `obs.SpanMetricsDropped`, existing tuples keep reporting). **Stale series are evicted at render** (`staleAfter`, default 15m, `"0"` disables, a NEGATIVE value is REFUSED — clamping it landed on the disable branch; `obs.SpanMetricsEvicted`) — without eviction the cap is a ONE-WAY LATCH, one burst of high-cardinality span names blinds RED metrics for every service that starts afterwards. A series is evictable only once a DELIVERED export carried its current values (`cumagg.Meta.State` observed→rendered→delivered); a re-created series gets a FRESH start timestamp, which is how OTLP spells the cumulative reset. The clock is read ONCE per `Consume`. **Zero-alloc warm path**: `observe` builds the map key on a stack buffer and looks up via `map[string(key)]`, materializing the dimension slice only when a new series is admitted (`TestConsumeAllocationBudget`). Exemplars are one per latency bucket, reset after each DELIVERED export, skipped for spans with no trace id or that the head sampler drops (`ExemplarKeep`/`SetExemplarKeep`). **`cumagg.MaxLabelBytes` bounds RETAINED BYTES, so a retained value is CUT WITH A COPY** (`cumagg.Retain` in `dims()`): a reslice keeps the whole original alive, and a 256-byte label was pinning a sender's 4 MiB `span.name` for `staleAfter`. `spanSize` is a cheap allocation-free estimate, not the exact proto size. Exported on `-ingest-span-metrics-interval` (default 1m) under the tier's own resource identity (`agentSelfResource`); the described service is a data-point dimension. Metric names follow the OTel Collector connector, NOT Tempo; `span.kind`/`status.code` VALUES use the proto enum spelling (`SPAN_KIND_SERVER`).
- **The trace tier / service graph** (`agent/servicegraph`, opt-in `-service-graph`, the ONE pipeline needing its own WORKLOAD): receives the cluster's OTLP traces and emits Tempo-wire-compatible EDGE metrics — `traces_service_graph_request_total`, `_request_failed_total` (emitted at zero too, so the error ratio is defined before the first failure), `_request_server_seconds`/`_request_client_seconds` histograms (two clocks; their difference is the operator's to take), labels `client`/`server`/`connection_type` (`""`|`messaging_system`|`database`|`virtual_node`)/`virtual_node` plus dimensions as `client_<dim>`/`server_<dim>`; per-bucket exemplars (`serviceGraph.exemplars`; the trace id is shared BY CONSTRUCTION, the span id is each half's own, cleared after a DELIVERED export). `Edge.Dimensions` is ORDERED canonically (`joinDims`, since the metric layer keys on the sequence) and BORROWED (aliases recycled buffers — a retaining sink must copy; that is what makes a dimensioned edge zero-alloc); values are cut by `cumagg.Retain` where STORED, never per span. Names are Tempo's VERBATIM, spelled so both OTLP→Prometheus translations reproduce them — the deliberate exception to OTel-dotted naming, because Grafana's Service Graph view queries those strings. **Pairing cannot happen in the DaemonSet** (the two halves come from two nodes). **TWO LISTENERS, and the port decides the treatment** (`cmd/kubescrape-agent/servicegraph.go`, receiver `sgreceiver.go`): the APPLICATION ports (`-service-graph-ingest-grpc`/`-http`, an `otlpingest.Server` with `Exporter: nil`) are UNAUTHENTICATED; the INTERNAL port (`-service-graph-listen=:4319`, `sgReceiver`) is bearer-authenticated because what arrives is TERMINAL (enriched, routed). The receiver borrows the shared wire guards — `NestingGuardOption(nil)` and `otlpingest.BodyReader` at `sgMaxRecvBytes` (an over-cap gzip must answer 413, not 400, because the sender is another kubescrape reading 400 as PERMANENT). Loop-freedom is STRUCTURAL (one directed edge, no Enricher or Resharder on the internal path); `ForwardedMarker` (`kubescrape.service_graph.forwarded`) is the second line: the application path REFUSES a marked payload with `InvalidArgument` (`obs.ServiceGraphReshardStat.LoopsBlocked`), the owner STRIPS it. **Enrichment happens at FIRST RECEIPT, never on the owner** (on the internal hop the peer is a sibling shard); `pipelines.peerIsOurOwnWorkload` vetoes a peer-IP attribution resolving to this tier's own workload (`obs.Ingested{peer_ip_rejected}`). **`Resharder`** (`reshard.go`) splits a push by ring owner (`ring.go`, Tempo's FNV-1 `TokenFor`, tokens from the shard NAME so every shard computes the identical ring; `Self` = `-service-graph-shard-name`, default `$POD_NAME`); `singleOwner` passes a one-owner payload through with no copy; trace-id-less spans stay local (`SpansUnkeyed`). **The hop is SYNCHRONOUS and FAILABLE** (the entry shard holds the only copy, so a dropped hop is a lost SPAN): a failed send fails the application's push (`otlpingest.GRPCForwardStatus`/`HTTPForwardStatus`), no queue, no `-buffer-dir`, `RetryAttempts: 1`; shares go out CONCURRENTLY. A part-way fan-out is at-least-once (the split is a pure function of the trace id) and RE-COUNTS accepted shares, so a failing shard (`Resharder.failing`) is sent first; a dead shard's arc is never reassigned. **The owner chain** (`buildOwnerChain`): `servicegraph.Processor.Tap → spanmetrics.Tap → tracesample → tailbuffer → collector`, forward-first-act-on-success, samplers at the BOTTOM so the graph and RED metrics see 100% of spans. **Deployment** (`templates/servicegraph.yaml`, `deploy/servicegraph.yaml`, `serviceGraph.*`, off by default): a **StatefulSet** (the ring addresses shards by ordinal DNS) behind a **headless** Service (`publishNotReadyAddresses: true`) for the internal hop, plus a ClusterIP `<release>-traces` Service for applications; no volumeClaimTemplate (state is in-memory; the StatefulSet buys NAMES), no ServiceAccount/RBAC, `podManagementPolicy: Parallel`, every per-node pipeline off INCLUDING `-ingest`. `serviceGraph.replicas` renders BOTH the size and `-service-graph-shards` — scaling is a `helm upgrade`, never `kubectl scale`. `serviceGraph.ingest.allowFrom` is the NetworkPolicy `from`; EMPTY MEANS ANY POD MAY PUSH. **Rendering does not hold the series lock**: `renderEdges` takes a `cumagg.Snapshotter` snapshot (512-series chunks) and builds pdata lock-free, because `RecordAt` runs inside the pairing store's mutex and a held series lock stalls every Consume (`TestRenderDoesNotStallRecord`); scratch reused under `renderMu` (lock order: `renderMu` before the store's). Bounds trade completeness for memory and count when binding (`obs.ServiceGraphExpired`/`ServiceGraphStoreFull`/`ServiceGraphDropped`/`ServiceGraphEvicted`) — a missing edge looks exactly like a call that never happened. Honest downsides: a hard cluster-wide dependency for traces, every span crosses the network twice, one noisy service shares the shards.
- **Service-graph config durations are STRINGS** (`Config.Wait`/`StaleAfter`; a `time.Duration` field failed `wait: 10s` and `UnmarshalStrict` rejected the whole file). `staleAfter` is parsed by `cumagg.ParseStaleAfter`; `"0"` DISABLES eviction. The agent-side span-attribute Trim is GONE (applications push traces to the tier); the db-attribute floor lives once in the shard's `databaseAttrs` (semconv-1.30 `db.system.name`/`db.namespace` beside Tempo's classic pair; `DefaultPeerAttributes` stays Tempo-verbatim, so a 1.30-only client mints no virtual node unless `virtualNodePeerAttributes` adds them). Incremental expiry's budget SCALES WITH THE BATCH (`min(SpanCount()+sweepFloorPerBatch, maxSweepBudgetPerBatch)` = 16384 total, spent in passes of `expirePerHold` = 1024 per lock hold (`edgeStore.expireInPasses`), stopping at the first short pass; the per-hold ceiling is NOT the total — `TestConsumeSweepsItsWholeBatchBudget`). A CLIENT/PRODUCER span with a ZERO span id is refused as unkeyable (it would key where every root server span keys and invent edges). `serviceGraphShards.port` defaults to `DefaultShardPort` = 4319 (pinned against `-service-graph-listen`); with `protocol: http` the URL takes `https://` when TLS is asked for in ANY form (otlpexport ignores `Insecure` for HTTP, so the scheme IS the TLS decision). `compileConfig` refuses `-service-graph` with both listen flags empty. On the CLIENT side any `databaseAttrs` attribute overwrites the kind-derived `messaging_system` (Tempo's rule); a server half never takes db classification. A resource with NO `service.name` is skipped at the resource level, counted `kubescrape_service_graph_unnamed_spans_total` for EDGE-CAPABLE kinds only (`spanSide`); the spans still forward and spanmetrics aggregates them under an empty `service_name`. Limitations: an edge needs BOTH halves — an uninstrumented callee appears only as a VIRTUAL NODE from `peer.service`/`db.name`/`db.system` (symmetrically an expired SERVER half names its caller as `virtual_node="client"`); no literal `"user"` virtual client (Tempo synthesizes one); dimensions resolve span-first (Tempo reads the resource first).
- **One cumulative-aggregator state machine** (`internal/agent/cumagg`): `spanmetrics` and `servicegraph` are two aggregators of the same SHAPE — a map of cumulative series keyed by a length-prefixed label tuple, admitted under a cap, evicted when unobserved, exported whole on an interval — and they were written twice and DRIFTED TWICE. `cumagg.Store[S]` owns the map, the mutex, admission (`AdmitLocked`, refusal counted through the caller's OWN counter), the observed→rendered→delivered gate (`cumagg.Meta`, embedded in each aggregate), stale eviction, the render/send/mark-delivered order, `ClampStart` (so a series admitted between `Export`'s single clock read and the render's first lock hold cannot emit `StartTimestamp > Timestamp`), the exemplar reset on DELIVERY, and `Run`'s loop plus its final DETACHED export; `Options.Render` is the one callback. Also shared: `ParseStaleAfter`/`ResolveStaleAfter`, `Builtins` (`Configure`), `AppendKeyPart`, `BucketIndex`, `Trunc`/`Retain` (`MaxLabelBytes` = 256), `AttrStr`/`ValueStr`, `DimValue`/`DimStr`, `SpanSeconds`, `Hist`, `Snapshotter`, `Exemplar` + `RecordExemplar`, the `SumMetric`/`HistMetric` shells. **The two drifts**: (1) `traceMetrics.staleAfter: "-15m"` was CLAMPED to 0 by spanmetrics — and 0 there MEANS "eviction disabled" — while servicegraph refused the same input; one `ParseStaleAfter` (empty = default, `"0"`/`"0s"` = disable, negative = an error naming the field, the value and the escape hatch; the DEFAULT returned beside every error so a constructor never refuses to aggregate) serves both, and `cumagg/drift_test.go`, deliberately an external test package, asserts both config surfaces reject the same string identically. (2) the built-in-label collision guard existed twice; `cumagg.Builtins` owns the rule (a colliding dimension is DROPPED — the attributes are one `pcommon.Map`, so a collision would blank the real label and render duplicate points) and both packages call it where their label NAMES become known (`Configure` at construction for spanmetrics, `Has` per Edge for servicegraph). **What deliberately did NOT move**: servicegraph's Tempo-verbatim names and two-histograms shape, the two separate `obs` counter pairs, spanmetrics' dimension set and size counter, each aggregator's snapshot element and `renderMu` — but the scratch (`Snapshotter`) and the LOCK STRATEGY are shared: BOTH snapshot under the store mutex in chunks and build pdata lock-free (spanmetrics used to build under one hold, and its tap calls `Consume` with the ingest RPC waiting, so every trace push blocked for the whole build once per interval — `TestRenderDoesNotStallConsume`). The other two whole-map passes were the unbounded ones: eviction is folded into the one pointer pass (`LivePointersLocked`) and the delivery mark (`afterDelivered`) walks only the series the render marked (`MarkRenderedLocked`) in the same chunks (`eachChunked`; `TestDeliveryMarkReleasesTheLockBetweenChunks`). Warm paths stay 0 allocs/op, ASSERTED (`spanmetrics.TestConsumeAllocationBudget`, `servicegraph.TestRecordIsAllocationFree`/`TestConsumeUnpairedIsAllocationFree`): the store's mutex is exported as `Lock`/`Unlock` precisely so the per-span fold stays straight-line code.
- **Trace sampling** (`agent/tracesample`, config `traceSampling`, on the `-service-graph` trace tier): consistent per-trace-ID probabilistic sampling (`tracehash.Keep` — deterministic across retries AND shards, so whole traces are kept; the algorithm is argued in the `internal/agent/tracehash` bullet and nowhere else, because WHICH traces are kept is a property of the hash FUNCTION) with keep-errors (default true) / keep-slower-than guard rails and a spans/second token-bucket cap (applied last, guard-rail keeps included). Wired near the bottom of `buildOwnerChain`, below both taps and ABOVE tail sampling; a payload sampled to nothing is acked without a send. Drops count `obs.TraceSpansDropped{reason=probability|rate}`.
- **Tail sampling** (`agent/tailsample` = the policy ENGINE, `agent/tailbuffer` = the BUFFERING/DECISION layer, config `tailSampling` embedding `tailsample.Config` so `policies:` stays flat, every duration a STRING; opt-in on the tier): whole-TRACE decisions. `Buffer` holds spans by trace id, calls `Evaluator.Decide` once `decisionWait` (5s) has elapsed since the trace was first seen, and exports or discards it whole; the halves meet ONLY at `Decide` (the engine holds no traces and imports no `obs`). **THE DELIVERY CONTRACT: this repo's ONE departure from ack-gated at-least-once** — a span is ACKED BEFORE its trace is decided (holding the RPC would pin an in-flight slot for 5s and stall every sender), so BUFFERED-BUT-UNDECIDED SPANS ARE LOST ON A HARD KILL. Bounded by TIME (`decisionWait` + a tick + the loop's own export time), by SIZE (`maxSpans`) and by SHUTDOWN (`run()` calls `Buffer.Flush` after the receivers stop and before the exporter closes; Flush LATCHES, so a straggler is decided on arrival under its own unowned ack — a SIGTERM loses nothing, only SIGKILL/OOM/node failure does), and VISIBLE before it is spent (`kubescrape_tail_sampling_buffered_spans`/`_buffered_traces`). **`maxSpans` is sized against REAL memory** (`memory.go`): `maxSpans × 1 KiB` must fit a QUARTER of the cgroup limit (or MemTotal); `New` LOWERS an unset default (not below `maxSpansPerTrace`), warns above the share, REFUSES a ceiling needing the whole limit — the likeliest hard kill is the OOM this buffer causes. Kept out of `Validate` (shape-only). **Bounds decide EARLY, never drop blind** (`enforce`): `maxSpansPerTrace` decides that trace on the spans present; `maxTraces`/`maxSpans` decide the OLDEST (closest to its natural decision); a partial trace is a LOWER BOUND (a slow trace can be missed, never invented); counted `obs.TailSampleEarly{reason=spans_per_trace|max_traces|max_spans|shutdown}` unless its window had closed. All-zero-trace-id spans are never buffered or cached (they would merge senders). **The decision CACHE** (`cache.go`, bounded by `decisionCacheSize`): a late span is forwarded on a keep, dropped on a drop (`obs.TailSampleLate{outcome}`, tallied when the push ACKS); the VERDICT expires at `decisionCacheTTL` while the record of what the decision SPENT (`Decision.Charged`) survives to the size cap and rides back as `tailsample.Trace.Charged`, a PER-BUCKET mask (`ChargedMask`) so a re-decision PEEKS the rate buckets it paid (`tracehash.Bucket.Peek`) and CHARGES the ones it did not; evicting a live verdict counts `obs.TailSampleCacheEvicted`. One mutex guards everything; NO export runs under it; the drain decides in CHUNKS (`decideChunk` = 128, `TestSweepDoesNotStallReceive`), since a decision can be a Starlark `decide(trace)` and the receive path takes the same mutex (with a `runtime.Gosched()` between chunks). The two failed-export lines hold SEPARATE throttles (`nackWarn`, fired from every receive goroutine, starved `lossWarn`, the only one naming spans actually lost). The arrival FIFO is deadline-ordered (`gone` flags + `compact()`). **Composition**: tail sampling is LAST in `buildOwnerChain` (the graph and RED metrics count REQUESTS) and NESTS with the head sampler. Caveat said out loud (`configWarnings` in `configwarn.go`, emitted by `-check-config` and every start): `traceSampling`'s guard rails are per SPAN, so `keepErrors`/`keepSlowerThan` deliver fragments to a whole-trace layer — WARNED, not refused, because `keepErrors` defaults to true; `probability` and `maxSpansPerSecond` are the supported half. **A DECIDED keep is DURABLE with `-buffer-dir`**: everything out of the BUFFER (the drain, a push carrying early keeps) leaves through `sendOwned`, marked `otlpexport.Own(ctx)` so `Buffered` SPOOLS it; without a spool it is retried on `sendContext` then dropped + `obs.TailSampleSpans{outcome=lost}`. Spooling at BUFFER time was rejected (an fsync in the ack path, 100% written to protect 1-10%, an in-order cursor that could not retire undecided traces). A failed forward of already-decided spans FAILS THE PUSH (the sender still holds them). Receive path allocation-disciplined (`TestReceiveLateDropAllocationBudget` 0 allocs; a DROP decision allocates nothing; policy label values resolved at `New` from `Evaluator.Names()` so a policy that never fired reads 0 rather than absent).
